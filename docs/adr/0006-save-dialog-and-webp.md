# 6. 保存交互采用系统「另存为」对话框 + 纯 Rust WebP

- **Status**: Accepted
- **Context**: PRD OUT-2 原写「PNG/JPEG 保存到默认目录，目录与命名规则可配置」。用户在实测连续截图时反馈：保存路径与格式都不可选；需要 WebP 输出；每次都走配置去改目录不现实。同时项目有两条硬约束：单文件免安装（避免 C 工具链依赖）与截图含文字（有损编码会伤文字边缘）。
- **Decision**:
  1. **保存一律弹系统「另存为」对话框**（`IFileSaveDialog`，`src/app/filedlg.rs`），不提供默认目录与默认格式配置；`Ctrl+S` 与工具栏保存按钮同一条路径。
  2. 与命名相关的配置只保留**文件名命名模板**（日期+时间 / Unix 毫秒时间戳 / 仅日期），用于预填对话框文件名。
  3. **记忆上次实际保存的格式**（`Config::last_save_ext`，覆盖层线程经 static 传给主线程在截图结束时写回配置），下次打开对话框默认选中该筛选器。
  4. WebP 采用 **`image-webp`（纯 Rust，VP8L 无损）**，而非 `libwebp` / `libwebp-sys`。
- **Consequences**:
  - 更容易：不用维护「默认目录 + 默认格式 + 质量」一组设置项；对话框自带最近位置记忆，用户在不同场景（桌面、项目目录、临时目录）都不必先改设置；连拍时靠「记住上次格式」避免反复切筛选器，同时保留每次显式确认的可控性。
  - 更难／代价：保存路径不可预算，脚本化或自动化导出需另开接口（当前不做）；`Ctrl+S` 不再是「静默保存」，与其他截图工具的习惯不同；`apply_panel_config` 必须显式保留 `last_save_ext`（面板工作副本是打开时的快照，整体替换会冲掉运行时记忆）。
  - 遗留：长截图（默认 `S`，可配置）与贴图右键保存仍直接存 `图片\jietu` 的 PNG，未走对话框与命名模板；WebP 有损与质量调节未做（PRD OUT-5 保留）。
