# 8. 文本字体选择（第二行工具栏 + 字体列表面板）

- **Status**: Accepted
- **Context**: PRD EDT-4（P0）要求「文本：点击放置，支持中文 IME 输入、字体、字号、颜色、可选背景」。M2 已交付 IME 输入、字号（滚轮）、颜色、双击再编辑；M5a 阶段 C 补齐字体族与粗体 / 斜体，并给字号一个可见的控件。截图工具的核心是「触发即用」，任何新增控件都要先证明它值得占位；同时覆盖层工具栏是自绘的，不能直接复用系统的字体下拉框。
- **Decision**:
  1. **字体数据落在对象模型**：`Kind::Text` 增加 `font_family: Arc<str>`、`bold: bool`、`italic: bool`（与既有 `font_size` 组成字体规格）。渲染侧统一经 `render::text::FontSpec` 传参，`render::text::remeasure` 是重建测量缓存的唯一入口，避免尺寸缓存与字体不一致。
  2. **字体列表 = 系统全部字体**：用 DirectWrite 枚举系统字体集（`IDWriteFontCollection`），名优先取 `zh-CN`、其次 `en-US`，过滤 `@` 开头的竖排别名，结果经 `OnceLock` 缓存（每次展开面板不再访问系统）。不做精选清单：用户装了字体就应该能用上。
  3. **面板是覆盖层自绘的可滚动列表**：固定 200×≤240，行高 22，行名用该字体自身渲染（所见即所选），当前字体高亮；优先展开在工具栏上方，空间不足翻到下方；点行选中、滚轮滚动、点面板外 / `Esc` / 切工具收起。
  4. **第二行工具栏只在文本场景出现**：文本工具、选中文本对象或正在输入文本时展开（工具栏高度 34 → 67），其余时候完全不存在。字号控件为「− 数值 +」三格（每步 2px，10–96），鼠标滚轮连续调节保留不变。
  5. **变更作用目标优先级**：正在输入的文本 > 选中的文本对象 > 新建默认值。前两者即时生效并进撤销栈（一次点击 = 一步撤销），默认值供下一次放置文本沿用；输入中改字体实时预览。
  6. **本期不做「可选背景」**：PRD EDT-4 的背景属于同一需求但不做，避免第二行元素过多，背景色的交互（开关放哪、用当前色还是独立色、文字是否反色）留待单独立项。
  7. **测试判据按实际栅格化像素**：中文字体（如微软雅黑）在 `DWRITE_FONT_WEIGHT_BOLD` 下字宽可能**更窄**，故粗体 / 斜体不用「测量更宽」断言，改用「着墨像素更多 / 像素图不同」验证真的换了字形。
- **Consequences**:
  - 更容易：字体选择从「隐藏功能（仅内置中文字体）」变成可见可控；字体族 / 粗斜体 / 字号三项共享同一条代码路径（`overlay::font` 的 `apply_font`），行为一致；面板与工具栏的脏区经 `chrome_rect` 统一合并，不引入新的全屏重绘。
  - 更难／代价：工具栏在文本场景变高 33px，小屏 + 大选区的极端组合下会压到信息文字（`toolbar::layout` 仅在剩余空间不足时退化，已由测试固定「能放下就不重叠」）；字体枚举与逐行渲染依赖 DirectWrite 可用，不可用时回退到仅默认字体（不崩溃）。
  - 遗留：`Kind::Text` 现在有 7 个字段，若后续再加（背景色、行距）应考虑收成嵌套的字体内嵌结构；`longshot/bar.rs`、`app/mod.rs` 等文件本就超过 300 行上限，本次未处理。
  - **陷阱（用户实测发现）**：`IDWriteFactory::CreateTextFormat` 的族名参数没有长度，只能按 `NUL` 结尾读取。给它的宽字符串必须手动补 `0`（`render::text::wide_z`），否则 DirectWrite 会读到缓冲区之后的堆内存：表现是「面板选了字体，输入的文本仍是默认字体」，空族名还会直接访问越界崩溃（`STATUS_ACCESS_VIOLATION`）。回归测试：`unknown_or_empty_family_falls_back_without_crashing`。
