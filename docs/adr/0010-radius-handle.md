# 10. 圆角改为对象上的内部控制柄

- **Status**: Accepted
- **Context**: 此前「圆角」是工具栏上的一个二值开关（`Action::ToggleRound`，开 = 固定 `ROUND_RADIUS = 12px`，关 = 0）。用户提出：应当像设计工具那样，在画矩形时直接在对象上给一个控制柄来调圆角，因此工具栏不必再占一个按钮。二值开关的问题很直接——12px 对 40px 的小标注太圆、对 800px 的截图区域又几乎看不出来，而界面上没有任何办法表达中间值。
- **Decision**:
  1. **删除工具栏圆角开关**：`Action::ToggleRound`、`State.round`、`Overlay.round`、布局项、绘制分支、`Icon::Round` 变体与 `round.svg` 资源一并移除。工具栏第一行 19 → 18 个按钮。
  2. **新建矩形默认直角**（`radius: 0`），由用户拖手柄调，不再有「默认圆角」这一概念。
  3. **控制柄位置**：包围框**内侧右上角**的白色小圆（半径 3.5，蓝色描边），与方形缩放手柄区分。
  4. **手柄随半径移动**：`inset = 14 + 0.293 × radius`，上限 `短边 × 0.45`。`0.293 ≈ 1 − 1/√2`，即圆弧 45° 点到角的距离系数——手柄看起来贴着圆弧走，半径变化时有可见反馈。`14px` 是下限：半径为 0 时弧就在角上，不内缩会和右上角缩放手柄（`PICK_RADIUS = 6`）抢命中区，反而拖不到。
  5. **拖拽方向按圆弧隐喻**：**朝矩形中心拖（左下）增大、朝角拖（右上）减小**。控制柄代表的是圆弧本身而不是数值，弧离角越远半径越大，所以往里拖就是变圆。
  6. **上限短边一半**：`Kind::corner_limit()`，`set_corner()` 内夹紧，与 `render` 圆角路径的收敛规则一致，拖过头不会把图形拖崩。
  7. **无累积误差**：每帧从按下时的半径重算（`r = r₀ + radius_delta(dx, dy)`），不做逐帧累加。
  8. **撤销粒度**：复用既有的 `begin_obj_drag` / `end_obj_drag`，一次拖拽 = 一步撤销，单击不动不留历史。
  9. **命中优先级**：`hit_handle` 里圆角柄先于八向手柄判定，否则永远被右上角手柄抢走。
  10. **自定义光标**：Win32 没有「调圆角」的内置光标，自绘 32×32 的「圆弧 + 弧中点小圆点」，白色形状 + 外侧 1px 黑边（暗/浅背景都可见），句柄缓存避免每次截图泄漏 GDI 资源。
- **Consequences**:
  - 更容易：圆角可连续调节且就地预览；小标注和大区域都能调到合适的值；工具栏少一个按钮（第一行窄了 30px）。
  - 更难／代价：多了一套手柄 + 光标 + 拖拽分支；`Kind` 的圆角读写散在 `editor/corner.rs`（`corner` / `corner_limit` / `set_corner`），新增矩形类对象时要走同一套入口。
  - **陷阱**：圆角柄和右上角缩放手柄在空间上天然冲突，只靠「最小内缩 14px」和「命中时圆角柄优先」两条同时成立才拖得到。改动 `PICK_RADIUS`、`RADIUS_GRIP` 或角手柄尺寸时，`radius_handle_wins_over_corner_handle` 测试会先失败。
  - 遗留：目前**只对矩形生效**。高斯模糊 / 荧光笔 / 聚光灯的模型里没有圆角字段（`Kind::Blur.radius` 是模糊强度而非圆角，`Kind::Highlight` / `Kind::Glow` 连半径都没有）。要支持它们需要各加一个 `corner` 字段，并改三处渲染：高亮的逐像素混合加圆角遮罩、模糊在回贴时按遮罩混合、聚光的「恢复亮度」从矩形拷贝改成圆角遮罩拷贝。
