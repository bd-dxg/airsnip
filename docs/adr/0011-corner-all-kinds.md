# 11. 圆角扩展到高亮 / 高斯模糊 / 聚光灯

- **Status**: Accepted
- **Context**: ADR 0010 把圆角从工具栏二值开关改成了对象上的内部控制柄，但只对 `Kind::Rect` 生效——高亮 / 模糊 / 聚光灯的模型里没有圆角字段（`Kind::Blur.radius` 是模糊**强度**，`Highlight` / `Glow` 连半径都没有）。用户要求这三类也能拖圆角，且交互与矩形一致。三类对象都是**逐像素**的区域渲染（覆盖面积可能整屏），所以任何圆角实现都不能拖慢 `corner == 0` 的既有路径（性能红线见 `docs/perf-m5.md`）。
- **Decision**:
  1. **数据模型**：`Kind::Highlight` / `Blur` / `Glow` 各加 `corner: f32`（新建默认 0 = 直角）。模糊的新字段一定叫 `corner` 而不是 `radius`，否则滚轮调强度的逻辑会误改圆角。
  2. **读写收敛在 `editor/corner.rs`**：`corner()` / `corner_limit()` / `set_corner()` 对四类统一生效，`corner()` 返回**夹紧后**的值（`remap` 不缩放圆角，对象缩小后靠读时收敛，不偷偷改用户设的值）。
  3. **手柄零改动**：`overlay::objedit` 的圆角柄走 `Kind::corner()`，加完字段自动出现在三类对象上；命中优先级（圆角柄 > 八向手柄）与光标（自绘圆弧）沿用 ADR 0010。
  4. **共享遮罩 `render/mask.rs`**：`corner_coverage(px, py, 完整矩形, r)` 给出像素中心的覆盖率（直边/中心直接 1.0，只有四角 `r × r` 方块内开方，做 1px 抗锯齿）；`copy_region` + `blend_compact`（遮罩处换成 src，聚光用）/ `restore_compact`（圆角处换回 src，模糊用）两个方向共用一套实现。
  5. **三处渲染接线**：高亮在「原像素 ↔ 染色像素」间按覆盖率插值；模糊先备份区域再就地模糊，最后按遮罩恢复角上原像素；聚光的「恢复亮度」在屏幕重绘（`overlay/selection.rs`）与导出烘焙（`render/bake.rs`）两处都改成遮罩拷贝，`corner_rect` 用**完整**对象矩形（导出时先减 `origin`）。
  6. **性能**：`corner == 0` 保持逐字节一致的快速路径；`corner > 0` 时用 `CornerBands` 预计算四角方块的行列范围，直边行/中段整块拷贝，只有角方块逐像素算覆盖率（实测 2560×1440 全屏高亮：直角 9.7ms / 圆角 8.1ms，与优化前的 25.4ms 相比回到基线）。
- **Consequences**:
  - 更容易：四类区域对象都能连续调圆角，屏幕显示与导出（`Ctrl+S` / 剪贴板）一致；圆角相关的几何/遮罩逻辑集中在两个文件（`editor/corner.rs`、`render/mask.rs`）。
  - 更难／代价：`Kind` 的三个变体多了一个字段，所有构造与模式匹配都要带 `..`；模糊在圆角下多一次区域备份 + 遮罩恢复（全屏模糊约 +20%，仍在既有模糊成本之内）。
  - **陷阱**（改动时先看这里）：
    - 脏区重绘时 region 被裁剪，圆角必须按**完整**对象矩形算，否则靠角的那次局部重绘会把角画成直角；
    - 模糊是就地修改，「原像素」只能在模糊前备份；
    - `CornerBands` 判为直边的像素覆盖率必须恰为 1（`bands_never_skip_a_partial_pixel` 守住这条不变量），否则角上会出现硬边；
    - 遮罩方向：聚光是「覆盖处换成原图」，模糊是「覆盖处保留模糊结果」，两者符号相反，混用会得到反色的圆角。
