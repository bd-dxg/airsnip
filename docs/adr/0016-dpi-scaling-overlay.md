# ADR 0016：覆盖层界面按显示器 DPI / 分辨率缩放

- 状态：已采纳（v0.7.0）
- 日期：2025-11-01
- 相关：CAP-2、CAP-5、EDT-4、EDT-7、LNG-1

## 背景

覆盖层（截图工具栏、选区手柄、对象手柄、尺寸提示、字体面板、自绘光标）与长截图状态条的所有尺寸
都是硬编码物理像素：工具栏按钮 26px、行高 34px、手柄 7px、尺寸提示字号 16px、光标画布 32px。

设置面板和托盘右键菜单从一开始就按 `GetDpiForWindow` 缩放了，只有覆盖层没有。于是在 4K / 200%
的显示器上，这些控件的**物理尺寸只有 1080p 的一半**——按钮小到不好点，尺寸提示小到看不清。

第二轮反馈暴露了第一个方案（纯 DPI 缩放）的盲区：**4K 分辨率 + 系统缩放 100%** 时 DPI 仍是 96，
自动系数算出来是 1.0，等于没生效。这类「屏幕像素密度高、但系统没缩放」的场景 DPI 感知不到。

## 决策

1. **新增 `overlay::ui::Ui`**，只做一件事：把 1080p / 100% DPI 下的基准像素换算成当前屏幕的物理像素。
   `Ui::px(f32) -> i32`（整数尺寸，至少 1）、`Ui::f(f32) -> f32`（浮点尺寸）。

2. **新增设置项「界面缩放」**（外观页，`settings::UiScale`）：自动 / 100% / 125% / 150% / 175% / 200%，
   默认「自动」。配置键 `ui_scale`，旧配置缺字段回退 `auto`。
   手动倍率直接生效，让用户能按自己的屏幕与视距调到舒服为止——这是纯自动永远猜不准的部分。

3. **「自动」取「DPI 缩放」与「分辨率补偿」的较大值**：

   ```
   dpi_scale   = 显示器有效 DPI / 96
   res_scale   = (屏幕面积 / 1920×1080) ^ 0.3
   auto        = max(dpi_scale, res_scale)   // 再夹到 [1.0, 3.0]
   ```

   - DPI 项处理「系统缩放已把界面放大」的常规场景（4K@200% → 2.0）；
   - 分辨率项处理「屏幕密度高但系统没缩放」的场景（4K@100% → 1.52，2560×1440@100% → 1.19，
     1080p@100% → 1.0）；
   - 取较大值意味着**已经调过系统缩放的屏不会被再放大一遍**：4K@150% 仍是 1.5（分辨率项 1.52，
     差 1%）、4K@200% 仍是 2.0。
   - 指数取 0.3 而非 0.5：4K@100% 的用户要的是「别太小」，不是「等比放大一倍」。

4. **缩放系数取「光标所在显示器」**：`GetCursorPos` → `MonitorFromPoint(MONITOR_DEFAULTTONEAREST)`
   → `GetDpiForMonitor(MDT_EFFECTIVE_DPI)` + `GetMonitorInfoW`（`rcMonitor` 拿物理分辨率）。
   覆盖层窗口横跨整个虚拟屏幕，`GetDpiForWindow` 只会返回窗口所在（通常主屏）显示器的 DPI，
   多屏混合 DPI 下会算错。取光标位置是因为触发截图时光标就在用户正在看的那块屏上。
   任一步失败都回退 1.0。

5. **整层统一一个系数，不做逐元素按屏缩放**。覆盖层创建时算一次，之后固定不变。
   逐元素按屏缩放在工具栏跨屏、字体面板跨屏时要动态换算，复杂度与回归风险都远高于收益。

6. **系数夹在 `[1.0, 3.0]`**。下限 1.0：100% 及更低不再缩小——本来就小的控件再缩只会更难用。
   上限 3.0：罕见的高缩放下避免工具栏占掉半个屏幕。

7. **常量改为 `*_BASE` 基准值**（如 `H_BASE: f32 = 34.0`），由 `ui.px()` 换算。基准值与改动前的
   硬编码值一致，所以 100% DPI 下行为完全不变（有单测守着）。

8. **自绘光标按尺寸缓存**（`AtomicIsize` + `AtomicI32` 记录画布边长）。尺寸变化（换屏后再次截图）时
   先 `DestroyCursor` 旧句柄再重建，不累积泄漏。窗口类的 `hCursor` 改用系统 `IDC_CROSS` 兜底，
   避免窗口类持有一个会被销毁的自绘光标句柄（真正的光标由 `WM_SETCURSOR` 主动 `SetCursor`）。

9. **标注内容不缩放**：线宽、字号、文字大小属于导出内容，跟着 DPI 变会改变输出结果，与用户预期不符。
   只有「操作界面」缩放。

## 影响

- 4K / 200% 下工具栏、手柄、尺寸提示、字体面板、长截图状态条、视口边框、预览窗、自绘光标
  的物理尺寸与 1080p / 100% 下一致。
- 4K / 100% 下自动放大到约 1.5 倍（用户仍可在设置里改成 175% / 200%）。
- 100% DPI + 1080p 下像素级行为不变（基准值就是原硬编码值）。
- 混合 DPI 多屏：以光标所在屏为准，其余屏的控件尺寸会与系统原生略有差异（可接受的取舍）。
- 设置面板与覆盖层共用同一个系数：在面板里选完倍率，面板本身当场就变大/变小，能直接预览效果；
  面板开着时按 F1 截图，覆盖层也已用新值（`ui_scale` 改动会标记 `config_dirty` 即时写回）。
- 4K@100% 下面板比系统控件大约 1.5 倍；若用户不喜欢，选「100%」即恢复系统原生尺寸。

## 测试守门

`toolbar_scales_with_dpi`、`bar_scales_with_dpi`、`panel_scales_with_dpi`、`preview_scales_with_dpi`、
`handle_hit_radius_scales_with_dpi`：200% 下各控件尺寸（含命中区）精确翻倍；
`scale_follows_dpi_and_clamps`、`px_rounds_and_never_returns_zero`：系数换算与夹紧；
`resolution_scale_is_gentle`、`auto_takes_max_of_dpi_and_resolution`：分辨率补偿的取值与「不被重复放大」；
`manual_scale_overrides`、`ui_scale_defaults_and_roundtrip`、`ui_scale_rows_map_both_ways`：
设置项持久化与面板行映射。
