# ADR 0017：快捷键支持清空为「未设置」

- 状态：已采纳（v0.7.0 开发期，对应看板 #63）
- 影响范围：`settings`（配置与面板）、`app::hotkey`（注册）、`app::tray`（托盘入口）
- 相关：PRD `SYS-2`、ADR 0003（管理员权限与任务计划）

## 背景

论坛用户反馈：快捷键无法设为空。设置面板只能把某项换成另一个键，想要「不抢这个键」只能换个键继续抢。
典型场景是截图热键 F1 与某个常驻软件冲突，用户只想关掉它，改用托盘菜单触发。

## 决策

1. **`0` 表示未绑定**（`settings::UNBOUND`）。字段仍是 `u32` 虚拟键码，配置结构不变，
   旧 `config.toml` 里不会出现 `0`，无需迁移。
2. **行内清除按钮**：每个快捷键行右侧一个方形按钮（`assets/icons/ui/` 的 `cross`），
   点一下直接置 `0`，不需要先进入捕获态，也不占用 `Del` / `Backspace` 作为清除手势
   （用户仍然可以正常绑定 `Del`）。已清空时按钮置灰，连点无副作用。
3. **显示层**：`key_name(0, _)` 返回「未设置」，不回落到 `MapVirtualKeyW`（否则显示「键 0x0」）。
4. **注册层跳过**：`register_one` 遇到 `0` 直接返回，不调用 `RegisterHotKey`，
   于是也不会弹出「错误码 87」之类的失败提示。
5. **冲突检测跳过**：`conflict_for` 忽略值为 `0` 的项，清空 A 后可以把 B 设为 A 原来的键。
6. **无修饰键提示不触发**：两个全局热键都清空时，`maybe_warn_no_modifier_clash` 不再弹窗
   （清空的键不会抢占任何按键，提示已无意义）。
7. **「恢复默认」需要确认**：快捷键页底部独立一行，弹出是/否确认后才覆盖 10 项
   （覆盖用户自定义值属于破坏性操作）。
8. **托盘必须留入口**：清空截图 / 贴图热键后，功能只剩托盘菜单这一条路，
   因此托盘菜单补上「截图」与「从剪贴板贴图」两项；清空这两个全局热键时先弹确认框说明该后果。

## 影响

- 配置文件可逆：`0` 只是普通取值，回退旧版本时该键会被当作无效虚拟键码（注册失败弹窗），
  用户重设一次即可；不涉及数据损坏。
- 面板布局：快捷键页从 11 行增至 12 行（新增「恢复默认」），窗口按内容兜底变高；
  键帽区让出 `CLEAR_BTN + CLEAR_GAP` 的宽度，`100% / 150% / 200%` 三档均保留 > 100px 键帽宽度（有单测守门）。

## 未采纳方案

- **把 `Del` / `Backspace` 当清除手势**：与「绑定 Del 键」需求冲突，且用户在捕获态下
  分不清「按 Del 是清除还是绑定」。
- **额外加 `Option<u32>` 字段表达未绑定**：会引入一层 `serde` 序列化差异与 `None`/`Some(0)`
  歧义，而 `0` 本来就不是合法虚拟键码，语义唯一。
