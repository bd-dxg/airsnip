# ADR 0022：OCR 用本地引擎，结果进独立文字气泡

- 状态：**已被 ADR 0035 取代并撤销**（原：已采纳，v0.8.0 开发期，对应看板 #61 的 OCR 一期）——本文仅作历史决策与实测结论记录，实现已整块删除，**不要据此恢复代码**
- 影响范围：`ocr`（新模块）、`overlay`（入口与裁剪）、`app`（气泡窗口与线程）、`settings`（新页签与配置）、`render`（气泡外壳绘制）
- 相关：PRD `OCR-1`～`OCR-13`、ADR 0005（贴图窗口线程）、ADR 0016（DPI 缩放）、ADR 0018（WinHTTP 与「不引入大依赖」）

## 背景

#61 要求支持 OCR 与翻译，但用户反馈「不是所有人都需要」，希望默认关闭。核心待决问题是**谁来做 OCR**：

| 维度 | 本地 `Windows.Media.Ocr` | 云 OCR API |
|---|---|---|
| 体积 | 0（系统组件） | 0，但要 key + 计费 |
| 上传 | 无 | 整张图 200KB–2MB |
| 延迟 | 几十～几百 ms | 1–3 s |
| 精度 | 屏幕渲染文本够用 | 更高（艺术字/噪声/复杂版式） |

截图工具的输入恰好是**屏幕渲染的文字**（清晰、无噪、字号稳定），是 WinRT OCR 的最强场景。

## 决策

### 1. OCR 默认走本地，云 OCR 只留接口

`Windows.Media.Ocr` 为零新增体积（只加 `windows` crate feature），图片不出本机，延迟比云 OCR 低一个数量级。
「云 OCR」不作为一期能力实现，只保留 `OcrProvider` 抽象位；等真实出现「艺术字/低质量截图识别不了」的反馈再补。

放弃的替代方案：直接上云 OCR（隐私与计费都不划算，且离线不可用）、离线模型（几十～几百 MB，与轻量目标冲突）。

### 2. OCR 读原图，不读输出图

识别输入是选区原图裁剪，**不含标注对象**。用户画箭头、打码的意图是「给别人看时别露」，把这些像素喂给 OCR 只会降低识别率，甚至把马赛克识别成乱码。
代价：用户如果故意用标注补了字，OCR 看不到——可以接受，OCR 与标注是两个目的。

### 3. 触发即结束会话，卡片独立存活

按 OCR 键（默认 `T`）的那一刻覆盖层立即关闭，卡片在主线程弹出。卡片是**主线程的独立窗口**，不是覆盖层的一块自绘区域。

理由：覆盖层是全屏 `WS_EX_TOPMOST` 窗口，卡片若挂在覆盖层上，覆盖层一关就跟着没；而用户对「OCR」的期待是拿到一段文字后继续干活（粘到聊天框、改错字、对照原文），卡片必须比截图会话活得久。
代价：识别结果要跨线程传回主线程（与贴图同款 `GlobalAlloc` 载荷 + `PostMessage`），并且要多一套窗口类、主题与 DPI 处理。

**形态取向是「划词翻译卡片」而非「对话框」**（用户反馈“感觉太重”后重做，参照 Bob 的窗口结构）：

- 三段式：顶部淡图标行（左图钉=置顶开关 / 右关闭）、中间带 1px 边框的文本区、底部行（左「复制」/ 右「自动复制」开关）；
- 文本区是**原生 `EDIT` 子控件**（见 §10），1px 边框由外壳绘制：常态 `divider`，文本区拿到焦点时换成强调色；
- 无阴影、无标题栏、无按钮条，只留圆角 + 1px 外边框（420px 宽 / 16px 字）；
- 图标常驻但用次级色（不靠悬停找入口，也不抢视线）；
- **卡片不自动关闭**（什么时候关由用户决定）；
- **自动复制默认关**：打开后每次识别成功自动写一次剪贴板（卡片上给 0.8s「已复制」反馈）；关闭时靠「复制」按钮或 `Ctrl+C`（有选区复制选区，否则全文）。
  开关状态在卡片里改了会通过 `WM_OCR_AUTOCOPY_CHANGED` 回写配置，与设置面板同一项。
- 拖动：除文本区外的任何空白处（顶部图标行、左右留白、底部）直接拖窗口。文本区是原生控件，鼠标事件不经过外壳，所以不再需要 `Alt`+左键那条例外通道。

**不显示「识别为 X」语言标签**：它的唯一用途是“识别错了能想到换语言”，但默认跟随系统时标签恒定，用户自己指定语言时又是重复信息；把语言信息挪到真正需要它的地方——错误文案里（「未识别到文字（当前语言：中文）」）。

**后续接翻译时**：在底部动作行下面加一条分隔线 + 每个 provider 一个译文块（服务名 + 译文），卡片宽度不变——结构已经为它留好了位置。

放弃的替代方案：覆盖层内自绘气泡（省事，但覆盖层关闭即消失）；带标题栏与按钮条的常规对话框卡片（第一版就是如此，实测观感太重）；全悬停图标（视觉最轻，但新用户找不到关闭/复制入口，也看不到识别语言）。

### 4. 功能开关默认关闭

一期只有一个开关：`ocr.enabled`（默认 `false`）。开启前 OCR 入口在界面上**不存在**（不注册按键、不初始化 WinRT、工具栏不出现按钮）。
二期接入翻译时再加 `ocr.translate_enabled`（默认关）：只想 OCR、不联网时关掉翻译即可。
不引入独立的 `local_enabled`——一期它和总开关是同一个东西，多一层只会让用户多点一下。
理由见用户反馈：多数人只想要截图，不该为一个可选能力付出常驻成本。

### 5. 多行结果按包围盒重排，行内按 CJK 判定补空格

WinRT 返回 `Lines`/`Words`。直接拼接会让英文变成 `HelloWorld`，全部合并成一段又会丢掉原排版。
更坑的是：**`OcrResult::Lines()` 的顺序不是阅读顺序**（实测按内部聚类乱序：同一视觉行的左段、另一行的左段、首行的中段、尾段……交错返回），而且同一视觉行会因为字重/样式变化被切成多段。

决策：
1. 每个 `OcrLine` 取全部 `Word.BoundingRect` 的并集当包围盒；
2. 按**垂直中心**归并成视觉行（阈值半个行高，行距 ≥ 1.2 倍字号不会误合并），行内按**左边界**排序，多段合回一行；
3. 行内**两侧都不是 CJK** 时才补空格（中文之间、中英之间都不加）；
4. 拼接后再做一次兜底剥离：把「两侧都是 CJK」的空格全部吃掉（防止语言包在词内塞空格，看起来像偏旁被拆开）。

翻译二期做段落合并时再单独处理。

### 6. 新增 `windows-future` 依赖（0.3.2）

`OcrEngine::RecognizeAsync` 返回 `windows_future::IAsyncOperation<OcrResult>`，该类型只实现了 `IntoFuture`，没有阻塞版 `get()`。
OCR 在后台线程同步等待结果，因此直接依赖 `windows-future` 并调用其 `Async::join()`（内部是事件等待，不引入运行时）。
该 crate 由微软维护、`MIT OR Apache-2.0`，依赖仅 `windows-core` / `windows-link` / `windows-threading`，与 GPL-3.0 兼容。
**不引入 tokio / async-std**：与「待机 0% CPU、常驻 ≤ 15MB」红线冲突。

### 7. 语言包缺失必须明说

`OcrEngine::AvailableRecognizerLanguages()` 为空或缺少所选语言时，气泡内直接说明「未安装 XX 识别语言包」并给「打开语言设置」入口，不静默降级成乱码。

### 8. 实测踩到的坑（写进代码注释，避免下一个人重踩）

- **位图字节要走 `IBufferByteAccess`，不是 `IMemoryBufferByteAccess`**。后者属于 `IMemoryBufferReference`（`LockBuffer` 之后 `CreateReference` 拿到），在 `Buffer` 上 QI 会返回 `E_NOINTERFACE`。另外 `Buffer::Create` 只给容量、长度默认 0，必须 `SetLength` 后再写字节，否则下游按 0 字节读。
- **不调用 `RoUninitialize`**。windows-rs 把激活工厂缓存在进程级静态表（`imp::factory_cache`），一旦 `RoUninitialize` 拆掉公寓，缓存里的 `IActivationFactory` 就成了悬空指针；同一线程再 `RoInitialize` 后复用缓存直接访问冲突（实测 `0xC0000005`）。因此 MTA 保持到进程退出，每线程用 `thread_local` 去重初始化。
- **小图先做整数倍放大**。引擎对 12～16px 的屏幕字体容易把一个字按偏旁拆成两个词；2 倍最近邻放大（≤1200px 时）后笔画变粗、不再被引擎内部降采样打碎。
  → **“≤1200px 才放大”是错的**（已改）：偏旁拆分的根因是笔画在引擎内部降采样时被打断，**与图宽窄无关**。实测 2003×160 的真实截图：1x 拆 4 处（`亻旦`/`氵益出`/`氵则量`），2x 全对，**3x 反而变差**。现在固定封顶 2 倍，仅受引擎 `MaxImageDimension` 与像素预算（放大后 ≤16M 像素≈64MB）限制。
- **`Lines()` 的顺序不可信**。用户实测截图里返回顺序是「第1行左段、第2行左段、第1行中段、第2行中段、第1行尾段……」，直接拼出来是乱的。必须用 `BoundingRect` 自己排（见 §5）。
- **卡片必须是分层窗口**。普通窗口里 `BitBlt` 上屏时圆角外没有任何像素，会直接露出黑底（实测四角发黑）；改用 `WS_EX_LAYERED` + `UpdateLayeredWindow` 后圆角才是真透明。
  → **该结论已被 §10 推翻**：分层窗口渲染不了子控件，圆角改 `SetWindowRgn`，边缘无抗锯齿但不再需要 alpha。
  → **非分层窗口画圆角会出黑边**：`BitBlt` 不认 alpha，圆角路径外的透明像素（预乘后 RGB=0）直接变成四角一圈黑。解法是**底色铺满整幅矩形**（不画圆角路径），圆角交给 region。
- **拖动不用 `WM_NCHITTEST` 报 `HTCAPTION`**。那样系统会接管鼠标，关闭/复制按钮的点击会被拖动循环吃掉（实测点 ✕ 无反应）；改成按下时自己 `ReleaseCapture` + `SendMessage(WM_NCLBUTTONDOWN, HTCAPTION)`（现在绑在 `Alt`+左键上）。
- **选字错位**：不能拿「累计宽度」直接与鼠标 x 比；要逐字符比较**前缀宽度中点**，否则落点会偏一个字符。
  → 自绘文本区整体已被 §10 替换，这条只在读旧代码时有用。

### 9. 划词卡片的约束

- **不自动关闭**：早期版本在复制后 0.8s 自动关，实测“刚复制完想再看一眼就没了”，已改为完全由用户控制（`Esc` / ✕）。因此图钉不再承担“钉住不关”，改为置顶开关（对照粘贴时不被遮挡）。
- **不提供专门的标题栏**：卡片太小，但需要能拖。拖动绑在“文本区以外的任何地方”，视觉上顶部图标行与四周留白就是自然的拖动区。
- **文本区常驻可编辑**（不再需要“双击进入编辑”）：真输入框的正常行为，单击即落光标，直接 `Ctrl+C/V` 就能用，少一层状态。识别中/错误说明两种状态切只读（文字仍可选中复制）。
- **每次 OCR 重置状态**：复制完成态与语言标签不继承上一条。
- **图标按墨水率单独配尺寸**：`Pin` 14.8% / `Check` 14.2% 天生偏轻，`Cross` 25.4% / `Copy` 28.6% 偏重，用同一系数画会让图钉比关闭小一号（见 `draw::icon_scale`）。

### 10. 文本区改用原生 `EDIT`，卡片不再是分层窗口

第一版把文本区当自绘区域做（自建文本缓冲 + 折行 + 选区 + 光标闪烁），结果是在手工重造 `EDIT` 控件，而且造不完：

| 能力 | 自绘实现 | 原生 `EDIT` |
|---|---|---|
| 输入法候选框跟随光标 | ❌ 一条 `WM_IME_*` 都没处理，候选框只能落在窗口左上角 | ✅ |
| 光标闪烁 | 手工 `GetCaretBlinkTime` + 定时器 | ✅ |
| 双击选词 / 三击选行 | ❌ | ✅ |
| `Ctrl+A/C/V/X/Z` | 只有 A/C | ✅ |
| 右键菜单（剪切/复制/粘贴/全选） | ❌ | ✅ |
| 输入超出可视区自动滚动 | ❌ | ✅ |
| 光标位置精度 | 按字符宽度累加估算，混排有偏差 | ✅ 真实排版 |

候选框不跟随的机制原因：位置不是输入法自己算的，而是宿主在 `WM_IME_STARTCOMPOSITION` 里用 `ImmSetCompositionWindow` 告诉它。自己接这套等于再写一遍输入法集成。

**PRD §8 风险表本来就写着「复用原生 `EDIT` 控件承接输入」**，第一版没照做，返工 6 次后改为原生控件。

代价与由此产生的连锁改动：

- **放弃 `WS_EX_LAYERED` + `UpdateLayeredWindow`**：分层窗口不能正常渲染子控件。圆角改 `CreateRoundRectRgn` + `SetWindowRgn`，代价是边缘无抗锯齿——卡片本来就没有阴影与半透明，视觉损失极小。
- **上屏改 `GetDC` + `BitBlt`**，窗口加 `WS_CLIPCHILDREN` 避免盖到子控件。底色必须铺满整幅（`bg` 的 alpha 强制拉满），因为 `BitBlt` 不认 alpha，半透明像素会变成发黑的边缘。
- **高度自适应不再自己折行**：先把文本区宽度定下来，再用 `EM_GETLINECOUNT` × `GetTextMetricsW` 的行高算内容高度，夹在最小/最大之间；超出最大高度后由 `EDIT` 自己滚动。
- **`EN_CHANGE` 要防重入**：程序自己 `SetWindowTextW` 也会触发 `EN_CHANGE`，用 `syncing` 标记屏蔽，否则每次填结果都重排两遍。
- **只读态换 `WM_CTLCOLORSTATIC`**：只读的多行 `EDIT` 收的是 `WM_CTLCOLORSTATIC` 而不是 `WM_CTLCOLOREDIT`，两个消息都要接，否则底色会变系统白。
- **`Esc` 要子类化**：`EDIT` 自己不吃 `Esc`，用 `SetWindowLongPtrW(GWLP_WNDPROC)` + `CallWindowProcW` 拦下转投父窗口。
- **换行符要转 CRLF**：`EDIT` 内部按 CRLF 记行，直接喂 `\n` 会被吞掉；读回来再统一转回 `\n`。
- **行高不能直接信 `GetTextMetricsW`**：`GetDC(hwnd)` 返回的 DC 里是**窗口类默认字体**，不是 `WM_SETFONT` 设进去的那个。实测默认字体报 `tmHeight=16`，而 YaHei UI 16px 的真实行距是 21px（`EM_POSFROMCHAR` 交叉验证：末行 y=147 / 7 行间距 = 21）。行数 × 行高把卡片算矮两行，表现为「识别文本完整，卡片显示不全」。解法：`line_h()` 里先 `SelectObject(dc, font)` 再 `GetTextMetricsW`，用完恢复；单测 `line_height_matches_real_layout` 拿 `EM_POSFROMCHAR` 对账。
- **删掉的东西**：`bubble/edit.rs`（文本缓冲）、`bubble/wrap.rs`（自建折行）、光标闪烁定时器，以及 `draw.rs` 里所有正文/选区/光标/滚动条绘制。

放弃的替代方案：继续补自绘方案的 IME 集成（`ImmSetCompositionWindow` + 自己算光标矩形，能修好候选框但修不好选词/撤销/右键菜单）。

## 后果

- 变简单：OCR 全程离线，无密钥、无计费、无隐私弹窗（翻译二期才需要）。
- 变复杂：多了一个独立窗口类（主题 / DPI / IME 都要重接），且覆盖层与气泡的线程边界需要在 `app` 里明确。
- 需要守住的线：功能关闭时待机成本必须与现在完全一致（`cargo test` + `scripts/perf.ps1` 验证）。
- 二期翻译可复用：气泡已是独立窗口，加「译文」区域与 provider 时不用再改窗口形态。
