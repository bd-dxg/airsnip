# 23. 标注叠层绘制与对象拖动通道

> **修订（ADR 0036）**：本文的「绘制优先」（§1）**仅适用于绘制态**（`editor::Mode::Draw`）。
> 截图框选完成后默认是移动态（`Mode::Move`）：此时拖选区内空白 = 平移选区，拖对象本体 = 移动该对象，
> 不再用当前工具绘制。§2 的三条显式拖动通道（框边 / `Ctrl` / 方向键）、§3 的无位移松手 = 选中、
> §5 的「光标与按下行为一一对应」在两种模式下仍然成立。见 `0036-move-mode-default.md`。

- **Status**: Accepted
- **Context**: issue #93 —— 用聚光灯框住一段文字后，改用荧光笔在该区域内拖拽，画不出任何东西，鼠标变成四向移动光标（实际进入了移动对象状态）。原因不是光标反馈，而是命中判定只有一条通道：
  1. `editor::Kind::hit` 对区域类对象（高亮 `Highlight`、模糊 `Blur`、聚光 `Glow`）与文本、填充矩形按「整块命中」处理（内部任意点都算命中）；
  2. `overlay::interaction::on_lbutton_down` 里，`hit_object` 一旦命中就立即 `begin_obj_drag(ObjHandle::Move)`；
  3. `objedit::hit_handle` 只判定八个缩放手柄与圆角手柄，**「移动对象」不存在独立的热区**。

  三者叠加的结果是：一块可选区域一旦盖住画面，其内部任何按下都变成「移动它」，新标注永远画不上。未填充矩形与箭头能叠层，纯粹因为它们只命中描边。原注释（`objedit::hit_handle`）写的「未填充矩形的内部是空白，按下应当能画新标注」与实现不一致——那条豁免对区域类对象根本不存在。

- **Decision**:
  1. **绘制优先**：对象内部按下不再启动拖动，而是用当前工具绘制新标注（文本工具直接放置输入框）。区域类、填充矩形、文本一律适用。
  2. **移动对象改走三条显式通道**，都保留在按下优先级里：
     - 选中对象的**包围框边缘环带**（宽 `pick_radius`，即手柄命中半径）→ 移动该对象；
     - **`Ctrl` + 命中对象本体** → 移动该对象（并自动选中）；
     - 方向键微调（既有，1px / `Shift` 5px）。
  3. **无位移松手 = 选中对象**：对象内部按下后不进草稿，直到鼠标位移超过 2px（与 `is_degenerate` 的 2px 判据呼应）才 `start_draw`。这样「单击选中、双击编辑」的既有心智模型不变，也不会留下 1px 垃圾对象；顺带避免聚光灯「按下瞬间全选区暗化」闪一下。
  4. **极小对象退化**：宽或高 ≤ 2×`pick_radius`（100% 下约 12px）时，框边环带覆盖整块 → 内部拖动仍视为移动，否则这类对象无法拖动。
  5. **光标与按下行为一一对应**（`cursor::cursor_at` 判定顺序与 `on_lbutton_down` 保持一致）：对象内部 = 十字（表示「这里会画」），选中对象框边 / `Ctrl` 悬停对象 = 四向，手柄 = 方向 / 自绘圆角，工具栏 = 箭头，空格 = 抓手。
  6. **不改** `editor::hit`：整块命中仍用于对象级操作——双击编辑文本、双击恢复直线、滚轮悬停调线宽 / 模糊半径 / 字号。改动集中在 `overlay` 交互层。

- **Alternatives considered**:
  - **只靠包围框与手柄移动**（不给 `Ctrl`）：更少隐藏修饰键，但移动区域类对象时抓手更挑剔，且对象很薄时几乎抓不到边。
  - **新增「选择 / 移动」指针工具**（工具栏第 7 个按钮，类似截图工具的选择器）：语义最干净、零歧义，代价是移动前必须切工具，且 `last_tool` 记忆到指针工具后下次截图默认无法绘制。
  - **「选中才能拖」**（非选中对象的内部点击先选中、第二次才拖）：仍然要两次点击才能选中，且第一次点击落在用户想画的位置会误选，问题只减半。

- **Consequences**:
  - 更容易：所有工具可以任意互相叠层，这是截图工具的核心用法；`cursor_at` 从此能诚实反映「按下会发生什么」；移动对象有了独立热区，不再依赖「对象内部」这条与绘制抢道的路径。
  - 更难／代价：**「拖动对象本体移动」被取消**，必须记住 `Ctrl` 或去抓包围框边缘；新用户可能先按一下发现只是选中，再学会 `Ctrl`。极小对象（小于约 12px）仍无法在其内部绘制——这是「可拖动」与「可绘制」的固有取舍。
  - 新增状态：`Overlay::pending_click`（按下点 + 命中的对象索引），在 `on_mouse_move` 判超阈值、在 `on_lbutton_up` 判选中，两处都不能漏；拖动中（`obj_drag` / `drag` / `ctrl_drag` / `draft` 非空）必须忽略它。
  - 触控板或无键盘场景可用：框边拖动与方向键微调不依赖修饰键。
