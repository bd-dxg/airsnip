# ADR 0027：取消截图的误触防护

- 状态：已采纳（对应 issue #114）
- 影响范围：`overlay/annotate`（`on_cancel` 分层与确认）、`overlay/wndproc`（Esc 分流）、`app/mod`（`confirm` 封装）、PRD `OUT-3`
- 相关：ADR 0019（鼠标键热键）、ADR 0020（悬浮提示）

## 背景

用户反馈（issue #114）：截图标注做了一半，不小心点了一下鼠标右键，覆盖层立即关闭，标注全部丢失。

改动前的现状：

- `WM_RBUTTONUP → Overlay::on_cancel()`，而 `on_cancel` **无条件** `cancelled = true` + `WM_CLOSE`；
- 不区分当前是否已有未保存的标注；
- 也不像 `Esc` 那样先收起取色 / 字体面板（`Esc` 与右键行为不一致）。

结论：右键即时取消本身是 PRD `OUT-3` 的既定需求，问题不在「有没有」，而在**丢失成本 + 行为不一致**。

## 决策

1. **取消分层回退**：`Esc` 与右键共用入口 `on_cancel`，按由内向外的顺序逐层回退 ——
   取色面板 → 字体面板 → 文本 / 序号输入 → 退出。一次误触最多只影响当前那一层。
2. **文本输入中右键 = 完成输入**：保留已输入文字并退出编辑态（等同 Enter / 点击别处），
   而非丢弃；`Esc` 才是取消输入（丢弃）。理由：右键在多数编辑器里等同「点别处 / 确认」，
   而 `Esc` 是约定的取消键。且 `Esc` 在输入态由键盘路径（`on_text_key`）优先处理，不经过 `on_cancel`，
   所以这一层实际只由右键命中。
3. **有未保存标注时二次确认**：若文档非空，退出前弹原生「是 / 否」确认框
   （「当前标注尚未保存，确定放弃并退出截图？」，owner 传覆盖层窗口以盖在其上），只有点「是」才退出。
4. **其余情况保持即时退出**：只有选区、没有标注时，丢失成本低，右键 / `Esc` 依然直接退出，
   不增加无谓的确认步骤。
5. **决策逻辑抽成纯函数** `annotate::cancel_step(...)`（可单测），UI（确认框 / 提交文字）留在边界调用。

## 关于「再按一次退出」

初次设计（PR #113）评估过「再按一次退出」，因需额外的屏幕提示层 + 一次性定时器 + 多处「其他操作即解除」的钩子，
状态与脏区管理成本高于弹框，改用了系统确认框。

issue #120 后重新评估：这些成本是可控的 —— 状态只在 `overlay/cancel_hint.rs` 一处（一个 `Option<(键, 时刻)>`
+ 一个提示矩形），定时器复用覆盖层已有的一次性 `SetTimer` 机制（与悬浮提示 tip 同款），
解除钩子只需在左键 / 滚轮 / 其它按键三处各加一行。换来的是非模态、跟随主题、不打断，故改为采用。

## 影响

- `overlay/wndproc` 的 `Esc` 分支简化为直接调用 `on_cancel`（面板关闭逻辑移入 `on_cancel`，去重）。
- 新增 `app::confirm`（`MessageBoxW` + `MB_YESNO` + `IDYES`）。
- 行为变更同步写入 PRD `OUT-3`。
- `cancel_step` 增单测覆盖各层优先级。

## 未采纳方案

- **右键仍即时退出，仅补 `Esc` 一样的面板分流**：不解决「误触丢标注」的核心诉求。
- **取消后暂存标注、支持恢复**：覆盖层已销毁、屏幕内容可能已变，需重新抓屏重放，性价比低。
- **把标注随取消一起保存**：违背「用户明确取消」的语义，且会产出用户没预期的文件。
- **取消时先清空选区再退（再按一次才退）**：标注都画在选区内，清选区却保留标注语义不自洽，徒增一次按键。

## 后续：取消改为「连按两次」（issue #120）

用户反馈（issue #120）：主动取消本来就表示放弃本次标注，每次都要点确认框反而干扰使用，而且确认框是 Win7 风格的经典样式，与界面不协调。

1. **新增设置开关**「连按两次退出」（`config.confirm_cancel`，设置面板「常规」页，**默认开**）。
   默认开是为了不悄悄撤销 PR #113 引入的误触防护，想要「取消即放弃」的用户自行关闭；
   关闭后决策 3 不再生效，有标注时右键 / `Esc` 也直接退出。
2. **二次确认从系统确认框改为「同键连按两次」**（`overlay/cancel_hint.rs`）：有未保存标注时，
   第一次 `Esc` / 右键只弹出非模态提示（贴在选区内部右上角；选区可用高度不到提示的两倍、或宽度塞不下时退到上方 / 上方无空间则下方；琥珀色提醒底），同一键在 **2s 时间窗内再按一次**才退出；
   换键或先做其它操作会解除待命；提示 2s 后自动消失（末尾 0.5s 渐隐）。即移动端「连按两次返回退出」同款交互。
   相比系统确认框：不打断操作、跟随主题，与「防误触丢标注」目的等价。
3. **manifest 声明通用控件 v6**（`Microsoft.Windows.Common-Controls` 6.0.0.0，`app.manifest` / `app.dev.manifest`）：
   此前未声明，系统对话框回退经典样式；声明后 `MessageBoxW` 等使用 Win10/11 视觉样式。
   零 Rust 代码，所有提示框（抓屏 / 保存失败等）一并受益。注意 `EDIT` / `BUTTON` 等为标准 User32 系统类，不受 v6 管辖。
4. **未采纳**：
   - **保留系统确认框（仅换 v6 样式）**：本 PR 早期方案；仍会打断操作、无法跟随深色主题，故改用第 2 条。
   - **覆盖层内自绘完整确认框**：可跟随主题，但需按钮 / 悬停 / 键盘 / 模态屏蔽，约 150–250 行；
     连按两次提示（无按钮、无命中）约 60–120 行即可达到同等防护。
   - **改用 TaskDialog**：排版更好，但同样不支持深色主题，收益有限。
   - **工具栏「退出」按钮 / `Esc` 可改键**：关闭开关后右键即可一键退出，二者都不再必要。
