# ADR 0027：取消截图的误触防护

- 状态：已采纳（对应 issue #114）
- 影响范围：`overlay/annotate`（`on_cancel` 分层与确认）、`overlay/wndproc`（Esc 分流）、`app/mod`（`confirm` 封装）、PRD `OUT-3`
- 相关：ADR 0019（鼠标键热键）、ADR 0020（悬浮提示）

## 背景

用户反馈（issue #114）：截图标注做了一半，不小心点了一下鼠标右键，覆盖层立即关闭，标注全部丢失。

改动前的现状：

- `WM_RBUTTONUP → Overlay::on_cancel()`，而 `on_cancel` **无条件** `cancelled = true` + `WM_CLOSE`；
- 不区分当前是否已有未保存的标注；
- 也不像 `Esc` 那样先收起取色 / 字体面板（`Esc` 与右键行为不一致）。

结论：右键即时取消本身是 PRD `OUT-3` 的既定需求，问题不在「有没有」，而在**丢失成本 + 行为不一致**。

## 决策

1. **取消分层回退**：`Esc` 与右键共用入口 `on_cancel`，按由内向外的顺序逐层回退 ——
   取色面板 → 字体面板 → 文本 / 序号输入 → 退出。一次误触最多只影响当前那一层。
2. **文本输入中右键 = 完成输入**：保留已输入文字并退出编辑态（等同 Enter / 点击别处），
   而非丢弃；`Esc` 才是取消输入（丢弃）。理由：右键在多数编辑器里等同「点别处 / 确认」，
   而 `Esc` 是约定的取消键。且 `Esc` 在输入态由键盘路径（`on_text_key`）优先处理，不经过 `on_cancel`，
   所以这一层实际只由右键命中。
3. **有未保存标注时二次确认**：若文档非空，退出前弹原生「是 / 否」确认框
   （「当前标注尚未保存，确定放弃并退出截图？」，owner 传覆盖层窗口以盖在其上），只有点「是」才退出。
4. **其余情况保持即时退出**：只有选区、没有标注时，丢失成本低，右键 / `Esc` 依然直接退出，
   不增加无谓的确认步骤。
5. **决策逻辑抽成纯函数** `annotate::cancel_step(...)`（可单测），UI（确认框 / 提交文字）留在边界调用。

## 为什么不采用「再按一次退出」

- 需要额外的屏幕提示层 + 一次性定时器 + 多处「其他操作即解除」的钩子，状态与脏区管理成本高于弹框。
- 模态确认框是「有未保存内容就关闭」的标准范式，语义无歧义；且**只在真正会丢工作时出现**，不是每次都打扰。

## 影响

- `overlay/wndproc` 的 `Esc` 分支简化为直接调用 `on_cancel`（面板关闭逻辑移入 `on_cancel`，去重）。
- 新增 `app::confirm`（`MessageBoxW` + `MB_YESNO` + `IDYES`）。
- 行为变更同步写入 PRD `OUT-3`。
- `cancel_step` 增单测覆盖各层优先级。

## 未采纳方案

- **右键仍即时退出，仅补 `Esc` 一样的面板分流**：不解决「误触丢标注」的核心诉求。
- **取消后暂存标注、支持恢复**：覆盖层已销毁、屏幕内容可能已变，需重新抓屏重放，性价比低。
- **把标注随取消一起保存**：违背「用户明确取消」的语义，且会产出用户没预期的文件。
- **取消时先清空选区再退（再按一次才退）**：标注都画在选区内，清选区却保留标注语义不自洽，徒增一次按键。
