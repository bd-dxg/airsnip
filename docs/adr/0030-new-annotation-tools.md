# ADR 0030：新增直线 / 椭圆 / 手绘自由笔画三个标注工具

- 状态：已采纳（v0.9.x 开发期）
- 影响范围：`src/editor/{mod,hit,transform}.rs`（新增 `Kind::Line` / `Kind::Ellipse` / `Kind::Freehand` 与对应 `Tool`）、`src/render/mod.rs`（三个绘制函数）、`src/overlay/{interaction/draft,pick,wheel,annotate,objedit/drag}.rs`、`src/settings/{hotkey.rs,panel/controls*,panel/keycap.rs,panel/interact/keys.rs}`、新增 `assets/icons/ui/toolbar/{line,ellipse,freehand}.svg`
- 相关：issue #134、ADR 0023（叠层绘制与拖动通道）、PRD EDT-13/14/15

## 背景

v0.9.0 的标注工具栏只有矩形、箭头、文本、荧光笔、模糊、聚光、序号 7 种工具，缺少三类常用基础工具：

1. **直线**：只有带箭头的直线（EDT-2），划线分隔 / 连接时箭头是多余的。
2. **椭圆**：完全没有圆形 / 椭圆，圈选重点只能用矩形或荧光笔。
3. **手绘自由笔画**：无法随手涂鸦、圈注、划线。

issue #134 要求补上这三项，且直线支持 `Shift` 画水平 / 垂直 / 45°，椭圆支持 `Shift` 画正圆。

## 决策

### 1. 三者都纳入现有矢量对象模型，不引入新渲染通道

新增 `Kind` 变体，与既有对象一样实现 `bounds` / `hit` / `translate` / `remap`，因此**选中、移动、八向缩放、方向键微调、撤销重做全部自动可用**（EDT-7 / EDT-11 的通道不变），不需要为每个工具写一套交互。

| 工具 | Kind | 绘制约束（Shift） | 填充 | 圆角手柄 |
|---|---|---|---|---|
| 直线 EDT-13 | `Line { from, to }` | `snap_direction`（水平 / 垂直 / 45°） | 无 | 无 |
| 椭圆 EDT-14 | `Ellipse { a, b, filled }` | `square_corner`（外接矩形→正圆） | 有（与矩形共用开关） | 无 |
| 手绘 EDT-15 | `Freehand { pts }` | 无（自由笔画） | 无 | 无 |

三者都不参与圆角控制柄、无曲线控制点——`corner()` / `control_points()` 走通配返回 None，与箭头/文本一致。

### 2. 手绘的存储与渲染

- **存储原始折线点列**（`Vec<Point>`），拖动时按**最小步距 2px** 采样：距离不足不记录，避免同一像素内高频移动产生海量点（`FREEHAND_MIN_STEP`）。
- **渲染时平滑**：用「相邻点中点 + 二次贝塞尔」——`move_to(首点)` → 首个中点 `line_to` → 之后每对相邻点以原始点为控制点 `quad_to` 到下一个中点 → `line_to(末点)`。曲线在采样点处圆滑过渡，观感接近真实画笔，且不改动存储的点列（导出/二次编辑仍用同一份点）。
- **命中测试**直接按折线距离（`dist_to_polyline`），与渲染路径一致：看到的笔画就是能点中的笔画。

### 3. 高频路径不做整列克隆，且点列跨快照共享

手绘拖动时 `update_draft` 每帧执行。若沿用其它 Kind「重建对象」的写法，需要对整个点列 `clone` 再 `push`，长笔画下是 O(n²) 累计。故在 `update_draft` 中把 `Kind::Freehand` 单独提出来**原地追加**（`&mut pts`），其余对象仍逐个重建（Copy 语义，成本可忽略）。这一分支同时避免了长笔画拖动时的帧抖动。

点列本身用 `Arc<Vec<Point>>`：撤销栈是**整份对象列表的快照**（`Document::begin` 克隆全部对象），
而 `document.rs` 的前提是「每个对象约 40 字节」。手绘是第一个 payload 随用户手势增长的 Kind，
不共享的话 100 层历史 × 全部笔画长度会线性膨胀。共享后历史快照只加引用计数，
只有被编辑的那一笔（`Arc::make_mut`）才真正拷贝，历史快照也不会被污染。

脏区也只取**新增段的局部**（`draft::segment_region`），而不是整笔包围盒：
笔画只追加，已画好的段不会变，重绘整笔在 4K 选区下等于每个鼠标事件都全屏回贴一次。

### 4. 椭圆命中用采样折线，填充用隐式不等式

椭圆是隐式曲线，精确点到椭圆距离需要解四次方程、不值得。命中判定：

- **描边**：按参数方程采样 64 段折线，再逐段算点到线段距离（不物化点列：本函数在鼠标移动的命中路径上对每个对象调用一次），外加包围盒早退——屏幕尺度下采样偏差远小于线宽。
- **填充**：直接用归一化不等式 `(dx/rx)² + (dy/ry)² ≤ 1` 判内部，无采样误差。
- **任一轴为 0 的退化椭圆视为误触**（`pick::is_degenerate` 用 `||`，与矩形的 `&&` 不同）：
  `draw_ellipse` 与 `hit_ellipse` 都会在这样的对象上早退，若按矩形判据保留，
  会留下一个既看不见也选不中的幽灵对象（只能靠撤销清掉）。

### 5. 快捷键沿用数字序列（8 / 9 / 0）

既有工具键是数字 1–7。新增三项取 **8 / 9 / 0**，保持「工具栏从左到右 = 数字键递增」的一致心智，不引入字母键与现有布局混淆。三者都进 `ToolKeys`，在设置面板「快捷键」页可改、参与冲突检测（工具键按虚拟键比较）。

### 6. 填充开关的作用域：当前工具**或**选中对象是矩形 / 椭圆

原 `ToggleFill` 对除文本/序号外的所有工具生效。直线与手绘没有填充概念，故作废该判据；
但新判据不能只看当前工具——否则「选中一个矩形 + 当前工具是箭头」这种常见状态下按钮会置灰，
选中的矩形就改不了填充了。故判据为「当前工具是矩形/椭圆 **或** 选中对象是矩形/椭圆」，
收敛在 `overlay::annotate::fill_enabled_for`，绘制置灰（`State::fill_enabled`）与动作副作用共用一份，
不再各写一遍。

### 7. 图标：手绘用 Material `draw`，直线 / 椭圆先用占位

手绘工具图标采用 Material Symbols 官方的 `draw`（笔 + 手绘轨迹，语义即「手绘」）。
直线 / 椭圆暂用满足规格（仅 `<path fill="currentColor">`、viewBox 自洽、墨水率 5%–48%）的占位几何路径，
**未取自 Material Symbols**——已知待办，后续替换为同套素材并更新 `assets/icons/ui/README.md` 的来源表。
实测墨水率（26px）：`line` 18.0%、`ellipse` 25.1%、`freehand` 16.1%，均落在组内区间。

## 影响

- 工具栏从 7 个工具增至 10 个；`Tool::ALL` 长度 7 → 10，`#[repr(u8)]` 判别值追加在末尾，`settings::last_tool` 的持久化语义不受影响（它有隐含前提「判别值 == `ALL` 下标」，现由 `tool_discriminant_matches_all_index` 守护）。
- 设置面板「快捷键」页键帽行从 12 项增至 15 项（5 热键 + 10 工具），两列排布后 8 行，仍落在固定窗口高度内。
- 工具栏第一行从 19 个按钮增至 22 个（100% DPI 下宽约 550 → 701px）；已补窄屏 / 高缩放下不越界的回归测试。
- 导出烘焙（`bake_objects`）与屏幕显示走同一 `draw_object_with`，三个新工具无需额外烘焙逻辑。
- 新增 14 项单测（直线/椭圆/手绘的 bounds/hit/translate/remap、渲染像素、烘焙平移、误触判定、
  默认键位、`Tool` 判别值与 `ALL` 下标一致、点列 `Arc` 共享不污染历史、手绘增量脏区、
  填充开关可用性、窄屏工具栏不越界），`cargo test` 334 项。
