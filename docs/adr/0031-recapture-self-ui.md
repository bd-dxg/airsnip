# ADR 0031：再次截图（截取本软件自己的界面）

- 状态：已采纳（v0.10.x 开发期）
- 影响范围：新增 `src/overlay/{recapture,opts}.rs`；`src/overlay/{mod,wndproc/mod,surface,init,interaction/mouse}.rs`；`src/settings/{hotkey,mod,panel/*}.rs`；`src/app/{actions,pin_edit,hotkey}.rs`
- 相关：issue #118、PRD CAP-8 / SYS-2、ADR 0028（贴图标注编辑）、ADR 0019（鼠标键热键）

## 背景

问题反馈（issue #118）：v0.9 之后**无法在截图中再截一张**。想截「AirSnip 自己的界面」（工具栏、选区、
标注效果，用于写文档 / 发帖 / 报 bug）时，按 `F1` 没有任何反应——`start_capture` 用
`OVERLAY_RUNNING` 互斥把重入直接挡掉了（重入 = 再抓一份全屏位图 + 再弹一个覆盖层，每份约 57MB）。
用户明确要求把「再次截图」绑到 `Shift+F1`，并在设置面板可改。

## 决策

### 1. 独立快捷键项 `hotkey.recapture_*`，默认 `Shift+F1`，且只在截图期间生效

新增 `HotkeyConfig::recapture_key` / `recapture_modifiers`（默认 `F1` + `Shift`），进设置面板
「快捷键」页（键帽行 15 → 16 项，两列排布后仍 8 行，固定窗口高度不变），可改键、可清空、参与冲突检测
（按「键 + 修饰」比较，`is_hotkey = true`）。

**不采用「Shift + 当前截图键」的推导方案**：那样改一次截图键就悄悄改了另一个键，用户无法单独调整；
也不采用「任何时刻都生效」，否则会长期抢占 `Shift+F1`。

### 2. 由**覆盖层线程自己注册**热键

`overlay::recapture::register(hwnd, opts)` 在 `overlay::run` 建窗后调用 `RegisterHotKey`，
`unregister` 在销毁窗口前调用。**不用主线程注册 + PostMessage 转投**，理由：

- 生命周期天然正确：热键的存活期 == 覆盖层窗口的存活期，不必在主线程维护「截图期间注册 / 结束注销」的配对，
  也不会出现异常路径漏注销。
- `RegisterHotKey` 是**按线程**归属的，覆盖层线程注册的热键其 `WM_HOTKEY` 直接派发到覆盖层窗口过程，
  省掉跨线程找窗口句柄（`FindWindowW`）或额外原子句柄。
- 覆盖层线程只注册这一个全局热键，窗口过程里出现 `WM_HOTKEY` 就只能是它，不需要再判 ID。

注册失败**静默**（`AIRSNIP_DEBUG=1` 时打印一行）：这只是截图期间的便利键，被别的程序占用时
退化成「取消后重新按截图键」，不该弹系统框打断正在进行的截图——这一点与主窗口热键
（失败必须提示，否则表现为「按了没反应」）不同，因为那里是唯一入口。

**贴图标注编辑模式（ADR 0028）不注册**：选区锁死为贴图内容，不存在「重新框选」。

鼠标中键 / 侧键不支持作为再次截图键（`RegisterHotKey` 不认，ADR 0019 的 Raw Input 通道归主窗口，
覆盖层拿不到）：配置成鼠标键时该键不注册，静默失效。

### 3. 「再截一张」= 把当前画面当新底图，原地重来（不重开窗口、不重抓屏）

覆盖层本身铺满整个虚拟屏幕，`display` 就是此刻屏幕上的内容。所以再次截图**不需要再调一次抓屏**：

```
original ← display        // 新底图 = 屏幕上正在显示的（含工具栏 / 选区 / 标注）
dimmed   ← dim(original)  // 重新生成暗图
display  ← dimmed         // 上屏缓冲回到暗图
first_paint = true        // 首帧无需再从 dimmed 回贴（与 init 首帧同理）
repaint(全屏) + apply_cursor_now
```

好处：无窗口闪烁（不销毁 / 重建窗口）、无抓屏开销与 HDR / 混合 DPI 的二次分支、内存不新增分配
（三份缓冲原地复制）。随后清空选区与标注回到「框选」阶段，用户框住那块画面即得「本软件界面」的截图；
旧选区 / 标注已经烘焙进新底图，正是用户看到的画面。

**没有选「销毁覆盖层 → 重新抓屏开新覆盖层」**：那样会闪一下桌面，且需要把 `OverlayOpts` 复制一份
（含 `PinEdit` 的像素图）才能重跑一轮 `overlay::run`。

**也没有选「嵌套第二个覆盖层」**：两套全屏位图 + 两套消息循环，收益为零。

### 4. 清空哪些状态

`recapture::reset_interaction` 把覆盖层恢复到「刚打开、还没框选」：文本 / 序号输入（放弃未提交内容并
重新禁用 IME）、字体面板、取色面板、悬浮提示、取消二次确认（含两个一次性定时器）、草稿、待定点击、
选中对象与手柄拖动、标注文档、选区、工具栏、长截图视口、取消标志。
**保留**工具、颜色、线宽、字号、字体等偏好——再次截图不该把用户的样式设置一起重置。

暗化系数抽为 `surface::DIM_K`，初始化与再次截图共用，避免两处各写一份 `255 - 120`。

## 影响

- 文件规模：新增 `overlay/recapture.rs`；为避免 `overlay/mod.rs` / `overlay/wndproc/mod.rs` 超 300 行，
  顺手把 `OverlayOpts` / `PinEdit` 移到新的 `overlay/opts.rs`（`mod.rs` 原样转出，外部引用不变），
  双击分支 `on_lbutton_dblclick` 移到 `overlay/interaction/mouse.rs`（纯移动，无行为变更）。
- `cargo test` 338 项（新增 4 项：默认值 / 往返、冲突检测、修饰位到 Win32 `MOD_*` 的映射、
  以及 `recapture::rebase` 的「当前画面当新底图且只暗一次」）。
- 设置面板快捷键页键帽行 15 → 16 项（6 热键 + 10 工具），仍是两列 8 行，固定窗口高度不变；
  「恢复默认」文案随之改为 16 项。本次又碰到「加一个键帽行要改 6 处平行 match」的老问题，
  收敛成 `KeyRowSpec` 表的后续重构已开 issue #140（不在本 PR 做）。
- 截图期间 `Shift+F1` 被本程序占用（仅截图期间，退出即释放）。
- 已知取舍：① 再次截图的画面**不含鼠标指针**（`display` 里没有硬件光标）；② 底图就是「当时屏幕上的画面」，
  所以上一轮的非选区暗化会一并拍进来——这正是用户当时看到的（选区内的内容是原亮度），
  但也意味着隔着两轮「再次截图」去框同一块桌面，会比第一次更暗；
  ③ 原有的可编辑标注会变成像素、撤销历史清空（不可恢复为对象），这一点已在 README 向用户说明。
