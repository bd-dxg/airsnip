# ADR 0032：选中对象单独删除（`Del` / `Backspace`）

- 状态：已采纳（v0.10.x 开发期）
- 影响范围：`src/overlay/annotate.rs`（删除动作 + 单测）、`src/overlay/wndproc/mod.rs`（按键派发）
- 相关：issue #71、PRD EDT-7 / EDT-12、**ADR 0007（本 ADR 部分推翻其第 1 条）**、ADR 0023（对象选中通道）

## 背景

问题反馈（issue #71）：标注只能 `Ctrl+Z` 撤回。撤回是**栈式**的——画了五个标注想删中间那一个，
撤回会把后面画的全部带走，用户只能重画。ADR 0007 当初下线删除功能的前提是「用户明确不需要」，
实测反馈推翻了它：**需要删除，只是不需要工具栏按钮和层级调整**。

ADR 0007 里已经写明「若日后恢复：可从 git 历史（PR #26，commit `7fcb914`）取回实现」，
但那条路径带回来的是一整套 `Action::Delete` + 工具栏按钮 + 层级调整，与本 issue 的诉求
（最小入口、只删选中的那一个）不匹配，故不取回旧实现，按下面的方案重做。

## 决策

### 1. 只有键盘入口，不加工具栏按钮、不加选中框按钮

`Del`（`VK_DELETE` = 0x2E）与 `Backspace`（`VK_BACK` = 0x08）在**有选中对象时**删除它。

- **不恢复工具栏「删除」按钮**：ADR 0007 的用户取舍（工具栏控件越少越好）依然成立，
  本次诉求是「能删」而非「好找」。按钮还会新增一个工具栏可见性元素（见 CONTEXT.md「工具栏可见性」），
  连带设置面板、脏区与悬停提示都要动一遍。
- **不加包围框角上的 ✕**：与圆角手柄抢位置（ADR 0010 的圆角手柄就在包围框内侧右上角），
  再叠一个删除按钮需要重新排布命中区，且缩放到极小对象时两者会重叠。

### 2. 键位**硬编码**，不进设置面板的键帽表

issue 原文提到「可以自定义键位」，但评估后不做：

- 这两个键是 Windows 通用的「删除」语义，改成别的键反而更难猜；用户真要用别的键，
  `Ctrl+Z` 撤回仍在。
- 键帽表新增一行会把快捷键页从 8 行变成 9 行（固定窗口高度被撑高），
  而收益只有一个「删除键」，不值。

**代价**：`Del` / `Backspace` 不在冲突检测表里，用户可以把它绑成工具键 / 长截图键 / OCR 键。
处理办法是**按键让让**：先尝试删除，`on_delete_selected` 返回 `false`（没选中对象、
或正在拖动 / 绘制中）时该键继续往常规派发走，于是工具切换照旧生效。
只有「绑成工具键的那个键」在选中对象时按下的瞬间会删对象——这一格冲突已在此记录，不再额外提示。

### 3. 只删选中的那一个，一步撤销，局部重绘

`Document` 早就有 `remove(index)`（ADR 0007 第 3 条保留下来给文本编辑用），
删除动作只是补上「快照 + 移除 + 归档」这三步（`delete_object`）：

```
doc.begin();          // 记录删除前的整份对象列表
doc.remove(index);
doc.commit(true);     // 归档为一步撤销
```

- **撤销能原样恢复**：删除是「少一个对象」的快照差异，`Ctrl+Z` 即回到删除前（含层序）。
- **局部重绘**：被删对象的包围盒（`bounds_to_clip` + `dirty_pad`）就是我们唯一需要重画的区域；
  与撤销 / 重做不同，这里**不需要整屏重绘**——撤销要重绘是因为另一份快照里的对象包围盒不可得，
  而删除前对象边界已知。工具栏矩形一并并进脏区，因为「撤销」按钮的可用性由灰变亮。
- **一个例外：删掉最后一个聚光对象**。聚光灯是「选区内**整体暗化** + 聚光区域恢复原亮度」，
  所以删掉最后一块聚光时，亮度变化覆盖**整个选区**；只重绘被删对象的包围盒会把其余区域留在暗化态，
  表现为「聚光灯删了，原地留一块暗斑」（实测缺陷）。故 `glow_before && !glow_after` 时脏区改为整个选区（外扩 `dirty_pad`）。
  这与 `start_draw` 里「第一块聚光按下即重绘整个选区」是对称的，两处都收在 `overlay/delete.rs` 的
  `glow_on` / `delete_dirty_region`（有单测守门）。
- **删完立即清空选中**：`selected` 是索引，其余对象会因 `Vec::remove` 前移，不清就会指向下一个对象。
  索引已失效（历史被 `Ctrl+Z` 换过）时只清选中、不吞按键。

### 4. 交互态下不吃这个键

拖动对象（`obj_drag`）、拖控制柄（`ctrl_drag`）、起笔草稿（`draft`）、
单击待定（`pending_click`）期间直接返回 `false`——这些流程正按索引改写同一个对象，
中途删掉会让拖动指向已消失的对象（与 `nudge` 的忽略判据保持一致）。
文本 / 序号输入中不经过这里：`WM_KEYDOWN` 开头就把按键交给 `on_text_key`，
`Backspace` / `Del` 在那里是删字符（EDT-4）。

### 5. 序号标记不重排

删掉「1 2 3」里的 2，剩下的仍是 1、3。这与 EDT-12 既有措辞一致
（「编号自动递增（取已有最大值 +1，删除 / 撤销不重排）」）：删除只移除对象，
不让画布上其它数字集体改变。

## 备选方案

- **工具栏按钮**：见 §1，会推翻 ADR 0007 的另一半取舍，且牵动工具栏可见性体系。
- **包围框 ✕ 按钮**：与圆角手柄位置冲突、极小对象上尤其挤。
- **键位进设置表**：多一行键帽、多一处冲突检测，收益不足（§2）。
- **删除后自动重排序号**：见 §5，会让用户画好的编号集体变化，且与 EDT-12 现有描述矛盾。

## 影响

- 文件规模：新增 `overlay/delete.rs`（删除动作 + 脏区判定 + 3 项单测）。没放进 `overlay/annotate.rs`：
  那里非测试部分已到 297 行，再塞就超 300 行硬线。`overlay/wndproc/mod.rs` 只多一个 match 臂。
- `cargo test` 347 项（新增 3 项：只删目标对象且一步撤销可恢复 / 聚光存在仍在暗化态 /
  删最后一块聚光时脏区改整个选区）。
- 已知取舍：
  - 删除**不可见**（没有按钮、没有菜单项），只能靠 `Del` / `Backspace` 或悬浮提示发现；选中对象后按 `Del` 不会二次确认（有撤销兜底）。
  - 删掉**文本对象**后第二行（字体 / 字号）是否收起仍看既有规则（「文本工具激活」也算满足），
    所以用文本工具输入文字、右键提交、再 `Del` 删掉该对象时，第二行会留着——它服务的是「下一次输入」，
    与本次删除无关。评审确认这也是期望行为，不改。
