# ADR 0033：工具栏元素可逐个隐藏（+ 撤掉 OCR 总开关）

- 状态：已采纳（v0.11 开发期）
- 影响范围：`src/settings/toolbar.rs`（新增，配置模型）、`src/overlay/toolbar/{mod,layout,draw}.rs`、
  `src/overlay/{init,opts,mod,selection,font,annotate,wndproc}.rs`、`src/settings/panel/{controls,draw,interact,toolbar_page}.rs`、
  `src/app/{actions,pin_edit}.rs`、`src/ocr/*`
- 相关：issue #143、PRD EDT-16 / OCR-1 / OCR-2 / OCR-13、
  ADR 0017（快捷键清空为「未设置」）、ADR 0028（贴图编辑模式）、ADR 0022（OCR）

## 背景

工具栏从 v0.4 的 6 个元素涨到 20+：10 个工具、5 个色块、填充、撤销、重做、贴图、长截图、OCR、复制、保存，
外加文本第二行。功能本身没错，问题是**所有人都被迫看见所有人的功能**——只用矩形 + 箭头 + 马赛克的人，
每次截图都要在一排按钮里找自己那几个。

同一时期 OCR 靠 `[ocr] enabled` 总开关（默认关）挡着：想用的人先去设置里打开，
不想用的人要理解「为什么有个功能默认关着」——一个功能两套心智成本，而界面本来该由显隐来管。

## 决策

### 1. 可见性是**纯视觉**偏好，配置只存隐藏集合

`ToolbarConfig { hidden: Vec<String> }`，键是稳定字符串（`tool.ellipse` / `color.3` / `edit.text_row` /
`output.ocr` / `file.save` …），写进 `[toolbar] hidden = [...]`。

- **只存隐藏集合，不存可见集合**：默认全可见 → 用户不动设置时界面与没有这个功能时完全一致；
  以后新增控件不进任何人的隐藏集合就自动可见。存可见集合会把新控件默认藏掉。
- **字符串键而不是枚举序号**：工具顺序会变（v0.10 就插了直线 / 椭圆 / 手绘），序号会串位；
  未知键（老版本写过、新版本已删的元素）读到后无害，也不会把任何东西藏掉。
- **隐藏 ≠ 禁用**：隐藏的保存按钮 `Ctrl+S` 仍能保存，隐藏的工具仍能用数字键切过去，
  隐藏的色块仍保留「上次颜色」。能力与绘制彻底解耦，这是本 ADR 最重要的一条。

### 2. 元素清单是 24 项（issue 里写的「16 个开关」是笔误）

> 注（ADR 0035）：OCR 已撤销，输出组由 3 项变 2 项、总数 24 → 23。下表保留当时的清单。

| 组 | 元素 | 数量 |
|---|---|---|
| 工具 | 矩形 / 箭头 / 文本 / 荧光笔 / 模糊 / 聚光灯 / 序号 / 直线 / 椭圆 / 手绘 | 10 |
| 颜色 | 5 个色块各自可隐藏 | 5 |
| 编辑 | 填充、撤销、重做、**文本第二行整行** | 4 |
| 输出 | 贴图、长截图、OCR | 3 |
| 文件 | 复制、保存 | 2 |

文本第二行**整行一个开关**（字体族 / B / I / 字号一起显隐），不拆逐元素——只留「B」会得到一个
26px 宽的第二行，比藏起来更没用。

### 3. 布局接 `Shown`，全空时**没有工具栏**

`toolbar::layout_ex` 的入参从「一串 bool」换成 `Shown { vis, text_row, show_output }`：

- 元素按 `ToolbarGroup::ALL` 逐组排布，组内全隐藏则整组消失，**组分隔线也随之消失**；
  分隔线位置改由布局算出的 `Toolbar::dividers` 提供（此前是「按动作锚点查位置」，
  一旦用户把锚点元素藏起来就会错位或留下孤立竖线）。
- `text_row` 与「文本第二行显隐」求与；`show_output == false`（贴图编辑模式，ADR 0028）
  与显隐是**叠加**关系：任一条件成立就不画输出组。
- 一个元素都画不出来时返回 `None`，`Overlay.bar` 保持 `None`：尺寸提示、脏区、命中测试都不需要特判
  （它们本来就都走 `Option<Toolbar>`）。宽度按可见项重算，`Toolbar.rect` 自然变窄。
- **已知边界**：极端组合下工具栏比屏幕还宽（如 1366×768 @ 200%，OCR 按钮常驻后 1392 > 1366），
  此时只能从左边距起画、右侧被裁。不给工具栏引入换行、也不改成右对齐（定位规则只留一套）——
  用户的出路正是隐藏不用的元素（README「已知限制」同步写明）。两条单测分别钉住现状与出路：
  `bar_wider_than_screen_is_left_aligned` / `hiding_groups_fits_narrow_hidpi_screen`。

  > 注（ADR 0035）：OCR 按钮删除后，1366×768 @ 200% 已能放下（宽 1332），超宽用例改到 1280×720 @ 200%。

### 4. 开局回落放在 `overlay::init`，判据是纯函数

`ToolbarConfig::settle_tool` / `settle_color`：要用的工具（`settings::last_tool()`）或当前色块被隐藏时，
落到 `Tool::ALL` / `0..SWATCH_COUNT` 里第一个可见项；一个都不可见时**保留原值**
（工具一个都没有也不影响绘制，色块一个都没有时标注照常上色）。
判据做成 `settings::toolbar` 的纯函数而不是塞进 `init`，是为了能单测（`init` 要全屏位图，测不动）。
会话内快捷键仍可切到隐藏项——回落只发生在会话开始。

### 5. 设置面板「工具栏」页：五组、统一 5 列、不引入滚动

面板没有滚动条，`H` 固定 520，且测试断言「宽 > 高」。最终几何：

- 组头行 26px（`GROUP_H`，比标准行矮），右侧紧贴组名一个 16px 三态勾选框：全显 ✓ / 部分可见 ─ / 全隐 □，
  整行可点（部分可见或全隐 → 全显；全显 → 全隐）。
- 元素行 46px，**所有组统一 5 列**（`ToolbarGroup::columns`）。统一列宽让「标签 + 开关」贴得够近，
  不会看错某个开关属于哪个标签；早先「工具 5 列 + 其余 4 列」的方案里，宽单元格的开关离自己的标签
  太远、离下一个标签更近，实测图确认后否掉。
- 合计 40（节标题）+ 5×26（组头）+ 6×46（元素行）= 446 < 520，**不需要滚动**。
- 标签长度受 5 列约束（单元格可用宽度 = 103 − 2×6 − 36 = 55px）：
  工具 / 色块标签一律 ≤3 字，「文本第二行」在 5 列下放不下，页面内改叫「字体行」。
  这条不靠肉眼守：`toolbar_cells_fit_label_and_toggle` 用 DirectWrite 实测字宽与单元格可用宽度比对。
- **文件组全部隐藏时页脚给一句话**：「工具栏上已无复制 / 保存按钮，Enter 仍复制、Ctrl+S 仍保存」。
  不拦全隐藏、不弹确认框——只是把「隐藏 ≠ 禁用」写在用户看得到的地方（R7）。
- 不做覆盖层内的显隐入口（右键菜单 / 悬浮「⋯」）、不做全局「全部显示」按钮、不做导入导出与多套预设。

### 6. 撤掉 OCR 总开关

> 注（ADR 0035）：OCR 已整块撤销，本节描述的字段、按钮、快捷键与设置页均已不存在，保留仅作当时决策记录。

- 删除 `[ocr] enabled` 字段，**旧值忽略、不迁移**：旧用户 `enabled = false` 升级后 OCR 直接可用
  （serde 默认忽略未知字段，`[ocr]` 段其余字段照旧读入）。
- OCR 按钮**默认可见**（统一规则，不给 OCR 特例）。副作用是升级后工具栏多一个按钮、宽一点。
- 隐藏 OCR 按钮**不**关掉 OCR 键：按 `T` 仍识别。彻底不用 OCR = 快捷键页把 OCR 键清空为「未设置」
  （ADR 0017）+ 隐藏按钮。
- **待机零成本不回退**：去掉开关后仍然**首次触发才初始化 WinRT**（引擎按需创建、用完释放），
  启动与截图路径上没有任何 WinRT 调用。`overlay` 里原来的 `ocr_enabled` 字段与三处判断一并删除。
- 设置面板「OCR 翻译」页保留（识别语言、识别后自动复制），只删「启用 OCR」那一行。

## 备选方案

- **存可见集合**：新控件默认被藏掉，与「用户不动设置就与现在一致」冲突。
- **用枚举序号当键**：工具顺序一变就串位（v0.10 刚插过三个工具）。
- **覆盖层内右键菜单 / 悬浮「⋯」显隐**：交互面变大、要新增命中与脏区路径，收益是省一次开设置面板；
  评估后按 issue 的 Out of Scope 不做。
- **让工具栏换行 / 自动缩窄**：会改动命中区与脏区模型，且「宽度自适应」在 20 多个按钮上很难好看；
  隐藏元素已经覆盖了「屏幕放不下」这个诉求。
- **保留 OCR 总开关、只是默认开**：仍然要用户理解「两个显隐入口」（开关 + 可见性），
  且「关掉开关」与「隐藏按钮」在界面上无法区分。

## 影响

- 新增 `src/settings/toolbar.rs`（元素表 / 分组 / 隐藏集合 / 开局回落 + 8 项单测）、
  `src/overlay/toolbar/layout.rs`（布局从 `mod` 拆出，保证单文件 ≤300 行）、
  `src/settings/panel/toolbar_page.rs`（组头勾选框 + 页脚提示）。
- `cargo test` 364 项（新增：隐藏集合往返 / 未知键无害 / 组三态与批量 / 开局回落 /
  隐藏后命中区与宽度 / 全空不绘制 / 第二行整行开关 / 分隔线随可见组 / 单元格字宽（四档缩放）/
  页脚提示不压行 / 遗留 `[ocr] enabled` 被忽略）。
- 已知取舍：
  - 快捷键页与工具栏页信息重复（工具键仍在快捷键页维护），接受。
  - 隐藏项在覆盖层内**看不到任何痕迹**（没有「显示已隐藏项」开关），与「界面越少越好」一致。
  - 面板不提供「恢复默认」以外的批量手段，组头批量已经覆盖主要场景。
