# ADR 0036：截图后默认「移动选区」（指针模式）

- 状态：已采纳（v0.11 开发期）
- 影响范围：`src/editor/{tool,document}.rs`、`src/overlay/{mod,opts,init,pick,cursor,wheel,annotate,recapture,selection,interaction/{mod,mouse,draft},toolbar/{mod,layout,draw,tip}}.rs`、
  `src/settings/{mod,hotkey,toolbar}.rs`、`src/settings/panel/{controls,draw,interact,controls/{layout,keyrows,keys}}.rs`、
  `src/app/{actions,pin_edit}.rs`、`assets/icons/ui/toolbar/move.svg`、`src/render/icon/data.rs`
- 相关：ADR 0023（绘制优先 / 对象拖动通道）、ADR 0027（连按两次退出）、ADR 0028（贴图编辑模式）、ADR 0033（工具栏可见性）、
  PRD EDT-11 / EDT-16 / EDT-17 / 4.7

## 背景

框选完成后，选区内**任何**按下都走「绘制」通道：拖一下就画出一个矩形（ADR 0023 §1 的「绘制优先」，当时是为了解决
「聚光灯盖住文字后画不上荧光笔」）。问题是这条规则把**最常见**的动作（挪一下框、把框对准一点）变成了「画一个不想要的矩形」，
用户得先 `Ctrl+Z` 撤销，再按住空格才能挪。空格是一个隐藏修饰键，发现成本高；而「画矩形」是一次明确的意图，不该是默认结果。

ADR 0023 当年把「加一个指针工具」列进 alternatives 并否决了，理由之一是「`last_tool` 记忆到指针工具后下次截图默认无法绘制」。
现在需求反过来：**默认就是移动**，绘制是需要显式选择的行为——那条否决理由不再成立。

## 决策

1. **引入交互模式 `editor::Mode { Move, Draw(Tool) }`**，它是「选区内按下会发生什么」的唯一判据：
   - `Move`（指针语义）：拖选区内空白 = 平移整个选区、拖对象本体 = 移动该对象；
   - `Draw(t)`：保持 ADR 0023 原样（对象内部拖动 = 用 `t` 画新标注，`Ctrl` / 选中对象框边 / 方向键移对象）。
2. **开局为 `Move`**：普通截图每次会话都从移动态开始，**不再记忆上次工具**（`settings::last_tool` 整块删除）。
   颜色、线宽、字号等样式偏好照旧记忆。
3. **切换**：工具栏「工具」组首位新增 **移动** 按钮（图标四向箭头，与移动光标 `IDC_SIZEALL` 同形）；
   点任一工具进入 `Draw(t)` 并保持（画完一个继续画同类），点「移动」或按 `V`（可改，设置面板「快捷键」页）回到 `Move`。
   `Esc` / 右键仍是取消截图（ADR 0027），不复用为「退回移动态」。
4. **光标诚实**：`cursor_at` 仍由 `pick_target` 决定，`Move` 态选区内为四向移动光标、`Draw` 态为十字。
   空格拖动（临时挪框）保留，两种模式下都可用。
5. **平移选区时标注跟随**（拖动与方向键一致）：`Document::translate` 整体平移对象列表，**不进撤销栈**——
   选区位置本身不可撤销，只把标注位置入历史会造成「框挪回来了、标注没跟着」的错位。
   拖手柄缩放选区仍只改裁剪范围，标注不动。
6. **双击空白的动作可配**（设置面板「通用」页，默认复制）：`双击选区空白 = 复制截图` / `= 贴到屏幕`（等价 `F3`）。
   双击对象（编辑文本 / 恢复直线）、双击色块（取色面板）不受影响；`Enter` / `Ctrl+C` 永远是复制。
   该开关与「贴图位置」都由两行单选改为一行开关，并**立即写回**配置（面板不用关，下一次截图即生效）。
   两行开关的**行文字随状态变**（`panel::draw::toggle_label`）：关 = 「…·复制截图」/「…·截图原位置」，
   开 = 「…·贴到屏幕」/「…·屏幕中间」——只写一半的话，用户看不出「关」是什么含义。
7. **贴图编辑模式（ADR 0028）例外**：选区锁定，移动态无意义，开局直接 `Draw(Tool::Rect)`，
   工具栏不画「移动」按钮，`Action::Move` 在该模式被忽略；`pick_target` 另有一道 `effective_mode` 兜底，
   防止任何路径把锁定选区平移掉（写回是按矩形裁剪的）。
8. **再次截图（`Shift+F1`）后回到 `Move`**：它等同一次新会话，与开局一致。
9. **滚轮在移动态下空白处无操作**：`Draw` 态的滚轮改的是「下次绘制的默认值」，移动态下看不见结果，只会制造隐形副作用；
   悬停对象上照旧调整该对象。

## 备选方案

- **只改选区内空白处、不加模式与按钮**：改动最小，但「怎么画」就得靠「先点工具栏工具」这个无状态动作表达，
  且没有任何地方显示「现在是移动态还是绘制态」，用户画半天画不出来。
- **把 `Move` 塞进 `Tool` 枚举**：会让 `Tool as u8` 与 `Tool::ALL` 下标约定（ADR 0030）多一个没有绘制语义的成员，
  `draft` / `wheel` / 字体行等所有 `match self.tool` 都得多一个空分支。独立 `Mode` 更贴合语义。
- **`Esc` 退回移动态**：与「连按两次退出」冲突（ADR 0027），会让误触退出变多。
- **保留 `last_tool` 记忆**：上次用矩形的人下次开局仍是绘制态，等于这次改动对老用户不生效。

## 后果

- 更容易：框选后拖一下就挪框，标注跟着走；想画标注点工具或在工具栏上看见当前态；双击动作按习惯配置。
- 更难的代价：**画标注多一步**（必须显式选工具）；`last_tool` 删除后，上一次用的工具不再自动沿用，连续多次画同一类标注时
  每次会话都要重新按一次数字键；贴在对象上继续画（ADR 0023 的原始场景）现在必须先切到绘制态。
- 新增状态：`Overlay::mode`（`tool` 字段被它取代，`mode.tool() == None` 表示移动态）、`Overlay::double_click`、
  `Config::double_click_action`、`ToolKeys::move_key`（默认 `V`）、`ToolbarSlot::Move`（配置键 `tool.move`），
  以及 `Shown::show_move`（贴图编辑模式不画移动按钮）。
- 工具栏多一个按钮（工具组 11 项），窄屏布局与设置面板「工具栏」页行数都需跟着复核：
  面板组头行高从 26 收到 24，给页脚提示留回 12px 呼吸空间。
