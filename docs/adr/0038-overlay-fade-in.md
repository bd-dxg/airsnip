# ADR 0038：覆盖层淡入（分层窗口常量 alpha）

- 状态：已采纳（v0.12 开发期）
- 影响范围：`src/overlay/{mod,fade,wndproc/mod}.rs`
- 相关：CAP-2（覆盖层显示）、ADR 0037（窗口吸附：首帧预画 + 半亮候选）、性能红线（交互 ≥60 FPS / 待机 0% CPU）

## 背景

覆盖层是「瞬间铺满屏幕并暗化」的：按下热键后画面从原样直接跳到暗图，观感生硬；
配合窗口吸附的首帧候选，用户能看出分层出现的先后（实测反馈过「明亮 → 极暗 → 半亮」的闪烁）。

要的是「淡入」：覆盖层从桌面淡出。

## 决策

1. **用分层窗口的常量 alpha 做动画**：显示前给窗口加 `WS_EX_LAYERED` 并把
   `SetLayeredWindowAttributes(LWA_ALPHA)` 的 alpha 置 0，显示后由一次性定时器链把 alpha 推到 255。
   每帧只有一次 API 调用，**零像素成本**——由 DWM 混合，与「无 GPU / 纯 CPU 渲染」的取向一致。
2. **动画结束立刻摘掉 `WS_EX_LAYERED`**（`GWL_EXSTYLE` 清位）并整窗重绘一次，回到原来的纯 GDI 上屏路径。
   交互期间不常驻分层合成，「交互 ≥60 FPS」红线不受影响；也避免长期依赖分层窗口的绘制语义。
3. **120ms / 8 帧（15ms 一帧）**，缓出曲线 `255 × (1 − (1 − t)²)`：先快后慢，前半程已走完六成，
   不会出现「前 60ms 像没打开」。末帧正好 255。
4. **一次性定时器，收尾即 `KillTimer`**：不引入轮询，待机 CPU 仍是 0%（定时器 id 4，与悬停提示 2 / 取消提示 3 并列）。
5. **`SetTimer` 失败就直接收尾成不透明**：宁可没有动画，也不能让窗口停在 alpha 0 变成"看不见的截图工具"。
6. **普通截图与贴图编辑都淡入**（同一个 `run`，不额外分支）。
7. **不加开关**：一次性、几乎零成本的视觉修饰，不值得占一行设置；有反馈再加。

## 备选方案

- **GDI 逐帧交叉淡入**（每帧把 `display` 在 `original` 与 `dimmed` 之间插值）：不动窗口样式、只影响暗化层，
  但每帧要全屏混合 + RGBA→BGRA + BitBlt——1080p 约 7ms/帧尚可，**4K 约 25ms/帧**，
  要么淡入明显掉帧，要么帧数砍到 3 帧变成「三级跳」，都不优雅。
- **`WS_EX_LAYERED` 常驻**：省掉样式切换，但整个截图会话的每次上屏都走 DWM 常量 alpha 合成，
  交互帧率需要重新采，且与「交互路径保持原有实现」的取向相反。
- **`UpdateLayeredWindow`（逐像素 alpha）**：仓库里贴图 / 弹出菜单 / 长截图条都用它，
  但它要求所有绘制都走 `UpdateLayeredWindow` 提交像素，与覆盖层现在的 DIB + BitBlt 路径不兼容——等于重写上屏。
- **只做两帧（原图 → 暗图）**：成本最低，但看起来还是「闪一下」，不优雅。

## 后果

- 更容易：覆盖层出现柔和；顺带**消除了首帧「明亮」闪一下**——窗口第一次映射时 alpha 为 0，
  用户看不到「已映射但还没绘制」的那一帧，第一眼看到的就是淡入。
- 更难的代价：窗口生命周期里多了一次 `GWL_EXSTYLE` 改动，摘掉样式后需要一次整窗重绘来让 DWM 拿到完整内容，
  否则可能留一帧半透明快照（已实现，需实测确认无可见瑕疵）；淡入期间是半透明窗口，
  前台 / 焦点可能在动画结束后才拿到手（收尾时补发一次 `WM_FOCUS_OVERLAY` 兜底）。
- 新增状态：`Overlay::fade_step`（帧计数）、`fade::{TIMER_ID, STEPS}`、`alpha_at`（纯函数，有单测守门）。
- 度量口径：热键→「可见」仍以首帧上屏为准（`perf::log_overlay_shown` 未改动），淡入的 120ms 不再额外计入。
