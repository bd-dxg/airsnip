# ADR 0040：快速选区键（全屏 `F` / 上次区域 `R`）

- 状态：已采纳（v0.13 开发期）
- 影响范围：`src/overlay/{quickselect,opts,init,annotate,wndproc/mod,interaction/mouse}.rs`、
  `src/settings/{hotkey,mod}.rs`、`src/settings/panel/{controls,controls/keyrows,controls/layout,draw,keycap}.rs`
- 相关：CAP-7（全屏选区）、CAP-2（框选）、ADR 0037 / 0039（窗口吸附与亮度三档）、
  ADR 0036（框选完成后默认移动态）、issue #140（快捷键元数据表）

## 背景

框选一个「整块屏幕」目前只有两条路：手拖到屏幕边缘（多显示器下很容易差几像素）、
或者靠窗口吸附单击（只对某个窗口有效，桌面空白处不行）。反复截同一块区域时，
每次都要重新拖一遍。

要的是两个覆盖层内的一次性快捷键：**`F` 框选光标所在那块屏**、**`R` 复用上次框选的区域**。

## 决策

1. **两个独立键位，进设置面板**：`hotkey.fullscreen_key` / `hotkey.last_area_key`，
   默认 `F`（`0x46`）/ `R`（`0x52`），归 `KeyBind::Plain`（覆盖层内按下即触发、无修饰键），
   与长截图键同组，可改、可清空、参与冲突检测。落点是 `KEY_ROWS` 元数据表加两项 ——
   与 issue #140 之后「新增一行只改表」的约定一致。
2. **全屏 = 光标所在显示器的 `rcMonitor`**（含任务栏），不是工作区 `rcWork`：
   「全屏」的字面意思就是整块屏，任务栏是屏幕的一部分；排掉任务栏要靠窗口吸附或手框。
   多显示器下取 `GetCursorPos` + `MonitorFromPoint(MONITOR_DEFAULTTONEAREST)` + `GetMonitorInfoW`，
   **鼠标在哪块屏就选哪块屏**。
3. **只在当前没有选区时生效**。已有选区（尤其已经画了标注）时按下去什么也不做：
   换选区必然要让旧选区的标注落到新选区外被裁掉，代价远大于「少按一次 Esc」。
   贴图编辑模式（ADR 0028，选区锁定）同理不生效。
4. **按 F / R 只选中，不自动完成**：与手框、窗口吸附单击走同一条确认路径
   （清候选 → 进调整态 → `set_selection` → 重绘被清掉的窗口半亮区），
   停下后停在移动态，接着标注或按 `Enter` 复制都行。**不自动复制**：
   一旦自动完成，同一个键就再也兼顾不了「框起来画两笔」。
5. **「上次区域」只记用户自己确定的选区**：手框 / 移动 / 手柄缩放的**松手**（`on_lbutton_up`）
   与 **窗口吸附单击**（`snap.pending` 分支）两处写入。
   **F / R 自己产生的选区不写回** —— 否则按一次全屏就把上次手框的位置盖掉，`R` 从此只会得到全屏。
6. **记忆只在进程内，不落配置**：`Mutex<Option<(i32, i32, i32, i32)>>` 模块级静态（`quickselect::LAST_AREA`），
   存**屏幕坐标**。不写配置文件的两个理由：重启后「上次」的语义本来就淡了；
   跨会话还要处理分辨率变化 / 显示器重排带来的坐标漂移，收益不抵复杂度。
7. **恢复时与当前虚拟屏求交**：显示器被拔掉 / 分辨率改了、区域只剩一半时自动裁小；
   交集为空时**静默不响应**（与「没有选区就按长截图键」的现有行为一致，不引入新的提示路径）。
   没有记忆（刚启动还没框过）同样静默。
8. **不加快捷键以外的入口**：工具栏不加按钮 —— 鼠标场景已有窗口吸附单击兜底，
   而工具栏「工具」组每多一个按钮，1366×768 @ 200% 这类窄屏就更接近被裁。

## 快捷键页排版（连带改动）

键帽行 16 → 18 项。两列并排会变成 9 行（内容高 40 + 9×46 + 92 = 546），
撑破固定的 520 高、把窗口变成近正方形，与「桌面窗口应保持宽 > 高」的约定冲突。
故快捷键页改为**三列 + 单元格内上下叠放**（标签在上 `KEY_LABEL_TOP`、键帽在下，
`KEY_CELL_H` = 56）：18 项 / 3 列 = 6 行，内容高 468 < 520，格宽 188 仍放得下
「工具·荧光笔」与 `Shift+F1`（有 DirectWrite 量宽单测守门）。

代价是快捷键页与其它节的视觉风格出现差异（叠排 vs 并排）。选它而不选「压行高」：
行高 46 → 38 会让悬停高亮与键帽上下只剩 4px，六行挤在一起更像表格而不是设置项。

## 备选方案

- **硬编码 `F` / `R`，不进设置面板**（`Del` / `Backspace` 的先例）：零配置面、排版不动。
  否决：这两个键是**唯一入口**，撞上用户自定义的工具键时没有任何避让手段。
- **进配置但不进界面**：用户看不出这两个键存在，等于只有读到源码的人能用。
- **`rcWork`（排除任务栏）**：少截一条任务栏，但与「全屏」的字面语义不符，
  且各显示器任务栏位置不同，用户无法预期。
- **有选区时替换选区（标注保留 / 清空）**：替换后标注要么落到选区外被裁、要么就得清空，
  两种都需要二次确认，交互比「先 Esc 再按」重得多。
- **记忆落盘（config.toml）**：跨会话可用，但要定义显示器拔出 / 分辨率变化时的降级规则，
  且「上次」跨重启后的可信度很低。
- **按 R 无可用区域时弹提示**：需要给取消提示组件（ADR 0027 后续）加第二种文案与定位，
  而它本来是给「取消确认」设计的；静默与既有按键行为一致。

## 后果

- 更容易：整屏截图一步到位，多显示器不用赌「拖到屏幕边缘」；重复截同一块区域只需 `R`。
- 新增状态：`Overlay::{fullscreen_key, last_area_key}`、`quickselect::{LAST_AREA, remember}`、
  `OverlayOpts::{fullscreen_key, last_area_key}`；纯函数 `clip_to_canvas`（求交，有单测）
  与 `monitor_rect_at_cursor`（Win32 查询）。
- 已知边界：`F` 取的是**按下那一刻**光标所在的屏，之后移动鼠标不会改选区（与本软件其它选区行为一致）；
  横跨两块屏的区域只能手框或窗口吸附选中，`F` 永远只框一块屏。
- 单测守门：`quickselect::tests`（记忆往返 / 退化矩形不入库 / 求交裁小与为空）、
  `hotkey::tests::quick_select_keys_default_to_f_and_r`（默认键不撞车）、
  `settings::tests::quick_select_keys_defaults_and_roundtrip`（旧配置回退 + 可清空）、
  `controls::tests::{hotkeys_use_three_columns, keycap_cells_stack_label_above_caps,
  default_key_caps_text}`（排版与键帽文案）。
