# ADR 0042：标注线型（实线 / 虚线 / 点划线）

- 状态：已采纳（v0.13 开发期）
- 影响范围：`src/editor/{linestyle,mod}.rs`、`src/render/{mod,stroke}.rs`、
  `src/overlay/toolbar/{mod,layout,draw,tip,line,linemenu}.rs`、`src/overlay/{annotate,linemenu}.rs`、
  `src/overlay/{opts,init,run,selection,wndproc,cursor}.rs`、`src/overlay/annotate/{style,cancel}.rs`、
  `src/overlay/objedit/drag.rs`、`src/settings/{mod,toolbar}.rs`、`src/app/{actions,pin_edit,wndproc}.rs`
- 相关：issue #168、PRD EDT-18 / EDT-16 / EDT-1 / EDT-2 / EDT-13–15、§5.1（渐变，后续）、
  ADR 0009（图标）、ADR 0016（界面缩放）、ADR 0023（绘制优先）、ADR 0033（工具栏可见性）、
  ADR 0036（移动态默认）、ADR 0041（快速保存）

## 背景

issue #168 要的是标注虚线。维护者本来还想做渐变，两者被归为同一类「样式」需求——
本次先交付线型，渐变按 PRD §5.1 另起一批。

线型与现有样式（颜色、线宽）有个本质区别：颜色和线宽**同时**决定新建对象与选中对象的外观，
而线型只对**有描边**的对象有意义——填充矩形 / 椭圆、高亮、模糊、聚光、文本都没有描边。

## 决策

### 1. 用 tiny-skia 自带的 `Stroke.dash`，不自研切段、不引 shader

`tiny-skia 0.12` 的 `Stroke` 带 `dash: Option<StrokeDash>`，`stroke_path` 内部会先 `Path::dash()` 再描边
（`painter.rs`）。也就是说矩形（圆角路径含三次贝塞尔）、椭圆、手绘折线、箭头线身、序号引线
**全部自动支持**，段长与相位由 `StrokeDash::new(vec![...], 0.0)` 控制。

放弃的两条路：

- **自研路径切段**：要自己平坦化贝塞尔 + 按弧长切分 + 重新组装多段路径，等同重写库里已有的
  `tiny-skia-path/src/dash.rs`，还多一处出错面。
- **dash shader**：`tiny-skia` 没有 dash 着色器，且 shader 只能按「像素/空间」做图案，弯线上会失真。

线型只换 `Stroke` 的两个字段（`dash`、虚线时的 `line_cap`），渲染入口仍是 `draw_object`，
所以屏幕显示、导出烘焙、贴图编辑烘焙共用同一条路径，不需要各写一遍。

### 2. 段长按线宽缩放

| 线型 | dash 数组（线宽 `w`） |
|---|---|
| 实线 | 无（走原有整段描边） |
| 虚线 | `w×3, w×2` |
| 点划线 | `w×6, w×2, w×1, w×2` |

固定像素的写法在 2px 细线下正常、10px 粗线下几乎看不出虚线；按线宽缩放让**相邻线宽的观感比例恒定**，
导出到不同分辨率也不走样。极细线兜底：每个数不小于 1px（否则 0.5px 线宽会算出亚像素段，渲染成噪点）。

### 3. 虚线一律平头端点，箭头三角保持实心

`line_cap` 在虚线 / 点划线时强制 `Butt`：圆头会把每段包成胶囊，2px 以下的间隙视觉上被吃掉一半，
看起来像密集点线。实线保持原行为（直线 / 手绘圆头，矩形 / 椭圆 / 箭头平头）。
箭头三角头仍然 `fill_path` 实心填充——虚线三角会碎得认不出方向。

### 4. 线型存在对象上，作用域与颜色 / 线宽一致

`Style.line: LineStyle`，随 `Object` 存进撤销快照。切换线型时：

- 有选中对象 → 直接改它（一步撤销，界面立即重绘）；
- 没有选中对象 → 只改「当前样式」，影响下一次绘制。

同理，模型里已有的对象天然带着自己的线型，缩放 / 移动 / 撤销重做不需要额外处理。

### 5. 只作用于有可见描边的对象

`annotate::style::has_stroke`：矩形 / 椭圆看 `filled`（填充时不描边，维持 `render::draw_rect` 现状），
箭头 / 直线 / 手绘 / 序号有描边，文本 / 高亮 / 模糊 / 聚光没有。

由此推出**置灰规则**（`line_enabled_for`）：有选中对象时只看它自己有没有描边；没有选中对象时才看当前工具。
选中填充矩形切虚线不会有任何反应，所以按钮必须置灰——这与填充开关「选中对象优先」的判据不同，
因为填充改的是对象自己的 `filled`，而线型改的是对象自己的 `line`。

### 6. 工具栏格子 + 自绘下拉（三项只有缩略图）

- 位置：编辑组「填充」右侧（`ToolbarSlot::Line`，配置键 `edit.line`），**占两个按钮宽**
  （52 基准像素）——单格 26px 画虚线时只剩一两个周期，三档区分不开。
- 格子内容：格子里画一条当前线型的真实样本（与下拉项共用 `toolbar::line::draw_sample`），
  样本右侧画一个小 ▾（`draw_chevron`）提示这一格点得开，样本矩形为此让出 9 基准像素；
  颜色沿用开关语义（启用且非实线 = 强调色，实线 = 主色，不可用 = 置灰）。
- 下拉：`toolbar::linemenu`，三项**只有线型缩略图、不加文字**（「虚线」与「点划线」两个名字
  在 26px 行高里反而更容易被读混）；当前项强调底色，悬停项悬停底色；点选项生效并收起，
  点面板外 / `Esc` 收起；展开期间吞掉点击，不穿透到选区和工具栏。
- 与取色面板、字体列表互斥；`Esc` 的分层回退中排在取色面板之后（`annotate::cancel`）。

### 7. 不给快捷键，跨截图记忆

下拉类控件没有「按下即生效」的键语义，硬塞一个循环切换键会让键帽表从 20 项涨到 21 项并新增冲突项，
故不提供。当前线型走静态槽 `editor::line_store` / `line_take`（与 `palette::colors_store` 同模式）：
覆盖层线程写入，主线程在 `WM_OVERLAY_DONE` 写回 `config.line_style`。配置值是稳定小写串
（`solid` / `dashed` / `dash_dot`），旧配置缺字段回退实线。

## 影响

- 工具栏可见性元素 25 → **26**（编辑组 4 → 5）；设置面板「工具栏」页编辑组 5 格正好一行，
  面板总高度不变（仍有 `hint_sits_below_last_row` 守门）。
- `tiny-skia` 的 dash 在 `stroke_path` 里每次都要把整条路径切一遍：虚线手绘的超长笔迹（上千点）
  会比实线多一次路径分配与遍历。本批不做缓存（草稿拖动只重绘新增段，实测未跨 60 FPS 红线），
  若以后手绘虚线出现掉帧，再把 dash 结果按对象缓存。
- 第一行多出 26 基准像素（线型格子占两格宽、52 而非 26）：1366×768@200% 从「刚好放得下」变成放不下。
  维护者明确**不考虑该组合**（现实中 1366 物理像素配 200% 缩放没有对应设备），
  已知限制仍按 EDT-16 的「隐藏元素」出路处理。
- `overlay::mod` 302 → 199 行、`overlay::annotate` 305 → 266 行（拆分出 `run.rs`、
  `annotate::style.rs`、`annotate::cancel.rs`），都在 300 行硬上限内。

## 后续（渐变）

渐变与线型是**正交**的两个维度（虚线渐变箭头是真实需求），所以：

- 数据模型上 `Style.line` 与将来的「涂色方式」分开放，不合并成单一枚举；
- 入口上渐变走**独立的色块**（维护者取向），而不是塞进这次的三项下拉；
- 需求口径已在 PRD §5.1：矩形描边 / 填充、箭头支持线性渐变（2–3 个色标，可调角度），
  实现用 `tiny-skia::LinearGradient`。

## 备选与放弃

| 方案 | 放弃原因 |
|---|---|
| 自研 dash 切段 | 重复库内 `dash.rs`，多一份平坦化与弧长计算，弯线接缝难守 |
| SVG 图标表达三档线型 | 图标是静态资源，无法显示「当前线型 + 当前色」，且三档差异在 26px 里画不清 |
| 下拉项带文字 | 两项名字相近，行高 26px 时文字占掉一半宽度，缩略图本身更直观 |
| 循环切换键（实线→虚线→点划线） | 键帽表 20 → 21 项、新增冲突检测，且「按三下回到实线」不可预期 |
| 填充对象也补描边以便显示线型 | 所有既有填充标注会突然多一圈边框（视觉回归），ADR 内已明确维持「填充不描边」 |
