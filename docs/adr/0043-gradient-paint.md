# ADR 0043：标注渐变（OKLab 全光谱、基准 + 套数推进）

- 状态：已采纳（v0.13 开发期）
- 影响范围：`src/editor/{gradient,style,palette,mod}.rs`、`src/render/{paint,mod,stroke}.rs`、
  `src/overlay/toolbar/{mod,draw,tip,layout,line}.rs`、`src/overlay/toolbar/colorpanel/interact.rs`、
  `src/overlay/{annotate,annotate/style,objedit/drag,interaction/draft,textinput,init,opts,mod}.rs`、
  `src/settings/{mod,toolbar}.rs`、`src/app/{actions,pin_edit,wndproc}.rs`
- 相关：issue #168（后续）、PRD EDT-19 / EDT-7 / EDT-16 / §5.1、
  ADR 0042（线型，与本项正交）、ADR 0016（界面缩放）、ADR 0033（工具栏可见性）、ADR 0036（移动态默认）

## 背景

线型（ADR 0042）交付时维护者提出：「样式」里还应该有渐变，但**不是彩虹色**——最多三四个色标，
同色系或邻近色，在色相环上「顺路」过渡，通透不显脏；而且「每一次渐变色和上一次不同」，
希望「根据上一次的颜色结束作为新的开始」。

PRD §5.1 原本写的是「矩形描边 / 填充、箭头支持线性渐变（2–3 个色标，可调角度），内置预设 + 自定义」，
那是「手选色标」的思路。本批按维护者的新口径改为**自动链式生成**，§5.1 的措辞同步调整。

## 决策

### 1. 色标在 OKLCH 里生成，插值在 OKLab 里做（`editor/oklab.rs`）

**脏区的真正来源是 sRGB 空间的线性插值**：sRGB 是 gamma 编码值，两色直接线性插值时，
通道同时下滑的区间会变成发灰发浑的「浑区」。本批把整条链路换到感知空间：

```
sRGB(u8) → 去 gamma → 线性 RGB → OKLab → 插值 → 线性 RGB → 加 gamma → sRGB(u8)
```

矩阵与 gamma 曲线用标准值（不可自行改系数），越界时**保持 L 与 h 不变、二分降 C**（不逐通道
clamp，那会偏色），alpha 走预乘语义（透明端与另一端同色时中间不会发黑）。

`editor::Gradient { stops: [[u8; 4]; 8] }`：一套渐变 = **赤橙黄绿青蓝紫 + 闭合点**，色相跨 **360°**。

| 色标 | 颜色 |
|---|---|
| `stops[0]` | 起点：第 n 套的基准色相（= 首次进入渐变时的纯色 + n×45°） |
| `stops[1..6]` | 沿色环等距推进：橙 / 黄 / 绿 / 青 / 蓝 / 紫 |
| `stops[7]` | 终点：h + 360°，**与起点同色（闭合）** |

- **为何闭合**：描边是沿周长走色的，起点与终点在同一个角上；若首尾不同色，矩形的左上角
  会有一道硬接缝（维护者截图指出「左上角颜色转换生硬」）。360° 回绕后首尾同色，接缝消失。

- **为何从「同色系」改成整个光谱**：维护者验收时明确「一个矩形里要看到赤橙黄绿青蓝紫，
  而不是红到橙两种色」——首版按「邻近色、不彩虹」实现，在 2–4px 描边上只看得到一个色系，
  完全不达标。本 ADR 的口径以维护者最终验收为准。
- **每套起点推 45°**：不再每次都从红开始；第 n 套相当于把整个光谱在色环上旋转 n×45°。
- **L / C 不跟基准色走**：整套色标统一到 **L = 0.80**，色度取该 (L, h) 下 sRGB 色域的**最大值 ×0.92**
  （`oklab::peak_chroma`）。跟基准色（红 L≈0.55）走的版本，黄绿青必然发浑发暗——用户验收时
  直指「过渡色浑浊」。统一高 L 后每个色相都是它在该亮度下最鲜的版本。
  代价：红在 L 0.80 下是亮红 / 珊瑚而不是深红，这是「明亮」与「深饱和」的固有取舍。

- **色相跨度 300° / 相邻色标 50°**：一条长边就能看完全光谱；对象间再旋转 45°。
- **用「基准 + 计数」而不是链式拿上一套终点当起点**：后者要经过 sRGB u8 往返，量化误差逐套累积，
  走几套后步长变短。`Gradient::nth(base, n)` 直接算第 n 套，有 `nth_advances_by_fixed_step`
  单测守门。
- **中点不靠插值**：显式抬 L 的中点让过渡始终「透」。
- **喂给渲染的是重采样后的 48 段**（`Gradient::sampled`）：tiny-skia 的 stop 间插值是 sRGB 线性，
  段足够短时误差不可见；采样时加一维 Bayer 抖动压色带（量化到 u8 前 ±0.5/255）。
- **无彩色另走 L 梯度**（C < 0.02，例如把色块改成白 / 灰）：色相没意义，沿 L 拉梯度。

### 2. 何时推进：**落笔成对象** + **换工具** + **双击色块**

- 画完一笔且对象真的入栈（`interaction::commit_draft` 的 `kept` 分支）→ 推进一套；
- 松手退化成「单击选中」（ADR 0023）→ 草稿丢弃，**不推进**；
- **换工具**（工具栏工具按钮 / 数字键切到绘制态）→ 推进一套（用户口径「换成箭头时就应该
  改变颜色」）；
- **双击渐变色块** → 即时换一套预览，不落笔也能先看；
- 单击纯色块 / 选中对象改样式 → **不推进**（只是使用当前那套）。

这样「连着画五个箭头」得到一条连续色带，而「点一下选中已有对象」不会偷偷换色。

### 3. 色块组：2 个纯色 + 1 个渐变，旧的 5 色迁移取红 / 橙黄

工具栏颜色组从 5 格缩到 3 格：前两格仍是可双击改色的纯色（默认红 `#E53935`、橙黄 `#FB8C00`），
第 3 格是渐变色块（画当前「下一笔」那套的**径向色块——中心白、边缘为起点色**，
而不是线性色带：22px 宽线性带里看不出色标变化）。维护者口径：白色很少用得上，
红 + 橙黄覆盖大多数截图标注。

配置 `swatch_colors` 从 5 项变 2 项，用 `de_swatches` 兼容旧文件：**旧 5 项取第 2、3 项（红、橙黄）**，
新 2 项原样读，不足时用默认。`color.3` 这个稳定键保持不变（第 3 格从「颜色3」变成「渐变」，
旧用户把它藏了的话会继续藏，属预期）。

### 4. 渐变是 `Style` 的独立字段，与线型正交

`Style { color, gradient: Option<Gradient>, width, line }`：

- 有 `gradient` 时渲染走渐变，`color` 退化为**代表色**（渐变中点）——文本、荧光笔、
  序号徽标的反白数字这些只认单色的地方继续用 `color`；
- 线型与渐变互不影响，虚线渐变箭头是合法组合；
- 「取消渐变」= `with_solid(color)`，与切换纯色块同一条路径。

### 5. 方向跟随对象几何，不用额外控件

| 对象 | 渐变方向 |
|---|---|
| 箭头 / 直线 | 起点 → 终点 |
| **矩形 / 椭圆 / 手绘（描边）** | **沿周长弧长走色**（`render/gradient_stroke.rs`）：每条边各走一段，上下边自然不同 |
| 矩形 / 椭圆（填充） | 包围盒长边：宽 ≥ 高 → 左→右，否则 上→下 |
| 序号徽标（填充） | 包围盒长边（圆即水平） |

> **为什么描边不沿直线方向**：早先描边跟填充一样按长边水平渐变，结果矩形上下两条边在
> 同一 x 处颜色完全相同（维护者指出「上下颜色一样」）。`LinearGradient` 只能沿直线走色，
> 所以描边改为：平坦化路径（含虚线切分）→ 按弧长重新采样成 12px 小段 → 每小段用局部线性渐变，
> Round 端帽让相邻段重叠避免细缝。
>
> **直角矩形特判**：内边空白且线型为实线时，4 条边各一次渐变（`stroke_rect_edges`），
> 从 ~90 次描边降到 4 次（多对象拖动时帧耗时差一个量级）。它用 **Square 端帽**使每条边两端
> 各外扩半个线宽、把四个角叠成直角——代价是外角比原 Miter 描边略“胖”半线宽，但零接缝。
> **虚线 / 点划线不能走这条快速路径**（Square 外扩会把虚线间隔补成实线），走分段。

实现用 `tiny_skia::LinearGradient`，并把**同一份对象→画布变换**同时交给 shader 与 `fill_path` /
`stroke_path`——导出烘焙（`draw_object_with`）时渐变与路径才不会错位。屏幕显示、导出、贴图烘焙
共用 `draw_object`，这条路径不需要各写一遍。

### 6. 作用对象：能涂色的图形，不含文本与荧光笔

支持：矩形（描边与填充）、箭头、直线、椭圆、手绘、序号（引线与徽标）。
不支持：文本（DirectWrite 单色混色）、荧光笔（低对比标记工具）、模糊 / 聚光（无涂色）。

判据 `annotate::style::gradient_enabled_for`：有选中对象时看它自己，否则看当前工具；
不可用时渐变色块画成灰带，点击也**不生效**（不会偷偷把 `color_index` 切到渐变而对象毫无变化）。

### 7. 交互：单击用、双击换一套；进度只在本次运行

- 单击渐变色块 = 使用当前这套（对选中对象生效，或作为下次绘制样式），**不推进**；
- 双击渐变色块 = 立即换一套预览（不开取色面板），格子里的白心色块随之更新；
- 选中一个已有纯色对象再点渐变色块 = 套上「当前预览那套」，不新生成；
- 渐变进度只存 `Overlay::gradient`，**不写配置**：重启后从当前纯色块的色相重新起手。
  维护者的口径是「连续画的时候不重复」，跨会话的记忆价值不大，而且写配置会让用户下次开局
  看到一个自己没选过的颜色。

## 影响

- 工具栏可见性元素 26 → **24**（颜色 5 → 3）；设置面板「工具栏」页颜色组 3 格。
- 第一行总宽 -52 基准像素（少两个色块）→ 加上线型格子的 +26，**1366×768@200% 重新放得下**
  （ADR 0042 里记的「放不下」就此撤销）。
- 配置迁移：`swatch_colors` 5 → 2 项（`de_swatches`）；旧 `color.4` / `color.5` 隐藏键变成未知键，无害。
- 渐变的每像素插值开销与纯色填色同量级（tiny-skia 渐变在扫描线里取样），大面积填充没有额外分配。
- `editor::mod` 拆分出 `editor/style.rs`、`render::mod` 拆分出 `render/paint.rs`，都在 300 行内。

## 已知边界

- 色相绕一圈（24 套）后会与第一套接近：这是「顺路推进」的必然结果，不做去重。
- 文本不支持渐变：要支持得改 `blend_glyphs` 的逐像素混色路径，本批不做。
- 手绘的渐变按包围盒走，不沿笔迹；沿笔迹需要把折线参数化，收益小。
- 渐变不提供透明度/角度微调；需要更复杂的渐变时，先看 §5.1 的「预设 + 自定义」是否要重启。

## 备选与放弃

| 方案 | 放弃原因 |
|---|---|
| 手选两个/三个色标（Photoshop 式） | 与「每次不同、上一次终点接下一次起点」直接冲突，交互也最重 |
| 色相大步推进（30–45°） | 十几套后落在品红 / 青这类难「不脏」的区段 |
| 只做明暗（不变色相） | 最安全，但连画十个对象看不出「每次不同」 |
| 彩虹 / 多色相渐变（用户明确不要） | 中间必然跨灰点，与「通透不显脏」相反 |
| 径向渐变（标注） | 小标注上看不出差别，多一层控件与状态（**色块图标**用径向白心，那是预览符号，不是标注涂色） |
| 渐变做成独立工具 | 渐变是「涂色方式」而不是「画什么」，做成工具会让工具组从 10 项继续膨胀 |
| 填充对象额外加描边以便显示渐变描边 | 会改变所有既有填充标注的外观（与 ADR 0042 同一取舍） |
