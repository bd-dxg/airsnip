# ADR 0044：长截图拼接容错（分段哈希 + 全位移择优、参考帧不回退）

- 状态：已采纳（v0.13 修复期）
- 影响范围：`src/longshot/{stitch,engine,session}.rs`
- 相关：issue #129 / #196（网页长截图提示拼接失败）、issue #157 第 2 点（视口内有动画就失败）、
  ADR 0029（长截图 HDR 抓帧会话复用）、PRD LNG-4 / LNG-5 / LNG-10 与 §6.3「已知限制」

## 背景

长截图自 M4 起就用「整行一个 64 位哈希 + 重叠区匹配行占比 ≥ `min_ratio`」定位滚动偏移。
两个实现层面的设计使它在真实网页上很容易失败：

1. **整行哈希要求像素完全一致。** 轮播图、GIF、闪烁光标、视频角标、进度条只要占了某几行的
   几个像素，这些行就整行不匹配；再加上 `min_ratio = 0.9`，动画区域一占内容区一成以上，
   无论其余九成对得多准，都判「定位失败」。
2. **「取第一个达标的最小位移」。** 达标就停、不比较各候选位移的好坏，所以阈值不能降：
   大片空白行会让很小的错误位移也「达标」。

`engine` 侧还有两个独立的错：

3. **失败时把参考帧换成了失败的那一帧。** 画布末尾对应最后一次成功拼入的帧，参考帧一前移，
   失败帧与上一个成功帧之间的内容就永久丢掉；动画越密集失败越频繁，拼出来的图断层越多。
4. **页眉 / 页脚检测只在「第二帧」做一次。** 第二帧是 90 ms 后抓的，用户通常还没开始滚动，
   两帧完全相同 → 代码判定静止、把页眉页脚高度清零。于是带吸顶导航或底部工具栏的页面
   每一段都重复拼入。

## 决策

### 1. 行签名分段（`stitch::RowSig`）

每行按宽度切成 8 段各算一个 FNV 哈希，**8 段里有 5 段一致就算「这行相同」**（`SEG_MIN_EQ`）。
动画只占行的一部分宽度时，其余分段仍然对得上，整行因此不再被判死。

### 2. 只给「有信息量行」计分，并全位移择优

- `info` = 与上一行签名不同的行。空白行、纯色行、重复行不计分，分母因此不再是内容高度，
  而是「真正有内容变化」的行数 —— 这才是可以放心降低阈值的前提。
- `min_ratio` 0.9 → **0.6**。
- 候选位移不再「第一个达标就停」：`s = 0` 与上下两个方向的全部候选（至少保留约 1/5 内容区
  作重叠，滚得快也能接上）都计分，**取得分最高者；分数差 < 0.02 视为平手、取更小位移**（保守）。
- 每个候选在「剩余行全匹配也达不到要求」时立即放弃（`need` 随当前最好成绩提高），
  静止帧与错误位移的开销基本是 O(1)。
- **`s = 0` 必须用「不剪枝」的方式求真实得分**（传 `need = 0.0`）：早版本把
  「`s=0` 得分低」与「有信息量行不足」当成同一件事，于是大面积背景的页面
  （论坛帖、白底文档）一滚动就走进「空白页只能判静止」的分支，**后面的候选位移一个都不会试**，
  表现为「往下滚，长截图不再记录」。真实日志里 `s=0` 得 0.41～0.49（<0.6）而真实位移
  `s=477` 得 1.000，却被判了“静止”——就是这个分支。

### 3. 参考帧只跟着「成功拼入」走

`prev` / `prev_sigs` 只在真正把内容拼进画布时前移；`Failed` 与 `Still` 都不动。
用户下一拍继续滚动、或动画恰好停在某个状态时就能接上，中间不再出现永久断层。
代价：失败后位移会继续累积，超过重叠上限（约 4/5 内容区）就需要往回滚一点 ——
失败提示因此改成「检测到滚动但拼接失败，请向回滚动一点或放慢速度」，
状态条提示改成「拼接定位失败，请向回滚动一点」。

### 4. 页眉 / 页脚留到「第一次真实滚动」再检测

首帧直接入画布；等到第一次 `confident && offset != 0` 时才用 `fixed_regions` 比对参考帧与当前帧，
**采纳条件是「带着这段页眉/页脚能定位成功，且位移非零」**，否则退回不排除固定区域的定位。
采纳时把画布首帧的头 / 尾行拆成页眉 / 页脚（`adopt_fixed`）。单边高度上限 **1/3 屏高**，
避免大面积同色页面把整屏吞成「页眉」。

**② 粘滞侧栏（`stitch::static_columns`）**：页眉/页脚只能处理「整行静止」的固定区域，
左右两侧的粘滞侧栏（论坛的话题侧栏、时间轴、聊天窗的左右栏、滚动条）是「整列静止」，
之前会被当成普通内容每拼一段重复一遍。现在真实滚过 ≥ 16px 后检测一次，一个列要同时满足两条才遮：

- **静止**：内容区逐行与上一帧一致（允许 `行数/50` 个行变化，即 ≈2%，滤瞬时提示）；
- **有内容变化**：该列在内容区有至少两种颜色。

**第二条是必需的**：白底正文里的白列、侧栏的空白边材也「静止」，但它们往往在后面的段落里
才出现真实内容（宽图片、表格）。早期版本没这条，检测出来的宽度一度到视口的 **54%**，
直接撞上安全阈值、整组作废——表现就是「右侧时间轴看着好了、左栏照旧重复」（右侧变好是巧合：
那个浮动框本身滚出去了）；实测数据：不加这条 778/1554 px，加上后 498/1554 px。

连续段 ≥ 8px 才采纳；粘滞内容只在结果顶部保留一次，之后拼入的行把那几列填成
**该段在内容区的代表色**（出现次数最多的颜色，最多跟踪 8 种），颜色太杂（图片 / 渐变侧栏）时
退回同行右侧相邻像素。遮掉的总宽度超过视口一半时**整组作废**（宁可重复也不能把正文遮掉），
同一会话最多试 3 次。

### 5. 帧签名缓存

`prev` 的行签名存在 `Canvas` 里，每拍只算新帧（`Signs::new`），省一半签名成本。
签名本身每 2 个像素抽 1 个采样（240 px 的分段仍有 120 个采样点），成本再减半。

### 6. 排障埋点

`AIRSNIP_DEBUG=1` 时每拍多记三个量，并在可疑时刻把「上一帧 / 当前帧」落成 PNG
（`%TEMP%\airsnip-longshot-{.png}`，单次会话最多 6 对）：

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `info=` | 内容区「有信息量行」数量（分数分母） | 很小（<6）说明页面几乎空白，定位容易陷入兼容分支 |
| `changed=` | 与参考帧「任一行不一致」的占比 | 持续 0% + `info` 很大 = 页面真的没动 或 抓到的是旧帧（看 PNG） |
| `still-but-changed` | 画面变了却判「无位移」 | 出现即说明决策可能错，同时落盘两帧 |

另外修了调试日志的时间戳：原来用 `Instant::now().elapsed()`，恒为 `[0]`；
现在按本模块首次调用起的毫秒数打，能看出冻结持续了多久。

## 定位过程（给以后的自己）

1. 用户日志里 346 次 `push` 全部 `confident=true`，**一次失败都没有** ——
   说明问题不在「匹配不上」，而在「匹配上了但选错了候选」。
2. `changed=31%~40%` 却 `offset=0` 是可疑信号：于是每 25 帧把「参考帧 / 当前帧」落成 PNG
   （只有它能告诉你画面到底动没动）。
3. 拿 PNG 用同一套算法（8 段哈希 + 5/8 容错 + 只数信息行）离屏复算，得到：
   `s=0` 得 0.41～0.49，真实位移 `s=300/477/574` 得 0.82～1.00 —— 错误分支当场暴露。
4. 修复后再用同一批 PNG 复算：6 对里 5 对从「静止」变成「拼入 offset=300/900/477/898/574」，
   真正静止的那一对仍然判静止（得分 0.986）。

**教训**：把「输入不够」（信息行不够）与「得分不够」写成同一个 `None`，
就会在带默认值的分支里默默断掉一条路；现在两者已经分开。

## 已知边界

- **纯色 / 极低信息页**：有信息量行不足 6 行时不做位移计分，`s = 0` 走全行比对兜底
  （只判「静止 / 不静止」），因此这类页面不会被误报「拼接失败」。
- **粘滞侧栏**：现在只在顶部保留一次、下方用相邻背景颜色填平；若希望保留重复效果，
  可以后续加一个开关（本轮没做，先看实际效果）。
- **滚动期间画面被重采样（平滑滚动亚像素、视频画面）**：行内容不再逐像素可重现，
  分段哈希仍会整行不匹配。这一条本轮**未处理**：曾在原型里试过「哈希前丢掉每通道低 2 位」，
  它会把「相差 1–3 个色阶的相邻行」抹成同一行，在合成页面上直接把偏移判错（拼出错误内容比报失败更糟），
  故放弃。
- **动画占内容区小半**（全屏视频、大面积粒子背景）时得分仍会低于 0.6 → 仍报失败。
  出路是缩小框选避开动画区，本轮没有做「自动排除每帧都在变的行」。
- **第一次滚动之后才浮出的吸顶元素**不会被识别为页眉，重复行属已知限制（PRD §6.3 已记）。
- **周期性内容**（细密条纹、等距表格）在 `2 × 0.8 × 内容高²` 的最坏情况下会让多个候选位移
  同时高分；平手取更小位移，可能拼少一段而不是拼错。

## 验证

- `stitch`：新增「局部动画 + 整行横幅动画仍能定位」「纯色页面判静止」「滚动超过半屏（1/5 重叠）
  仍能定位」「页眉里有小块动画仍被识别为固定区域」「**大面积背景的页面真实滚动不会被判静止**
  （issue #196 根因，修前该用例红）」「粘滞侧栏识别为静态列」「整帧未变时不遮任何列」七个用例。
- `engine`：新增「失败不换参考帧，下一帧还能接上」「第二帧静止、首次真实滚动才拆页眉/页脚」
  「**带 GIF 头像的论坛帖子页逐段拼入**（issue #196：头像每帧都在变、沿页面重复出现）」
  三个用例；原有「带页眉页脚滚动拼接」「向上滚动前置」「高度上限」「撤销」用例全部保持通过。
- 真实页面复验仍待维护者用 `AIRSNIP_DEBUG=1` 的 `%TEMP%\airsnip-longshot.log` 中的 `push:` 行确认
  （关注 `confident=false` 出现在哪些位移上）。
