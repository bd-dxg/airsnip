# 45. 徽标对勾 / 叉号（EDT-20）—— 序号标记扩展为三态内容

- 状态：已采纳（v0.14.0）
- 影响范围：`src/editor/number.rs`（`Badge` / `BadgeMark` / `next_number`）、`src/editor/mod.rs`（`Kind::Number.mark`）、
  `src/render/badge.rs`（徽标绘制，从 `render::mod` 拆出）、`src/overlay/{annotate,badgemenu,number_edit,textinput,objedit,interaction}`、
  `src/overlay/toolbar/{badgemenu,draw,line,mod,tip}`、`src/settings`（`badge_mark`）
- 相关：issue #186、EDT-12（序号标记）、ADR 0026、ADR 0042（下拉面板）、ADR 0045

## 背景

issue #186 想要「和序号标记一样，但徽标里放 ✓ / ✕」，用于截图批注里标「这里对 / 这里错」。
参考对象是 Snagit 的图章功能。

需求本质是**同一个对象换内容**，不是新工具：徽标圆、引线箭头、字号滚轮、命中 / 包围盒 / 平移缩放 /
撤销重做，序号标记都已经有了。

## 决策

### 1. 不新增工具栏按钮，序号工具升级为「徽标」

工具栏第一行宽度已经贴着 1366×768 @200% 这条线（ADR 0042 / 0043 为它反复调整过，EDT-19 缩掉两个色块才重新
放得下）。新增「对勾」「叉号」两个方形按钮 = +52 基准像素 + 两处间距，会把这条组合重新打回「超宽被裁」。

因此保持**一个工具**，把内容从 `n: u32` 扩成三态：

```rust
enum Badge { Num(u32), Check, Cross }   // 对象内容
enum BadgeMark { Num, Check, Cross }    // 形态（配置记忆 / 下拉高亮用，不带具体编号）
```

`radius` 本来就是渲染层测量后缓存进对象的字段，所以 `bounds` / `hit` / `transform`（`..` 模式）无需改动。

### 2. 对勾 / 叉号不占用编号

`next_number` 只看 `Badge::Num`。于是同一张图里混着放 `1`、`✓`、`✕`、`2`，编号仍是 1、2，不会因为符号
被跳号；反过来，切回编号形态时取「文档内最大值 +1」（ADR 0026 的「创建即定号」不变）。

### 3. 符号用矢量描边，不用字符

`✓`（U+2713）/ `✕`（U+2715）在微软雅黑里都有，但：

- 用户可以把文本字体族换成任意系统字体，缺字时徽标里会变成豆腐块；
- 不同字体的勾叉宽度与基线差很多，与徽标的圆形比例对不上，看起来时大时小。

所以用**两段圆端折线**画勾、**两条圆端线段**画叉（`render/badge.rs` 的 `MARK_CHECK` / `MARK_CROSS`，
比例坐标相对徽标半径），线宽 `0.30 × 半径`。半径与单个数字同宽（`0.6 × 字号` 估宽），视觉重量一致。

### 4. 形态入口：格子右下角的下拉三角 + 双击徽标改内容

**放置前选**：序号格子右下角画一个 ▾ 三角（`BADGE_CORNER_BASE` = 9 基准像素），点它弹自绘下拉
（`toolbar/badgemenu.rs`，与线型下拉同一套布局：工具栏上方优先、空间不足翻到下方、三项只有缩略图），
选中即生效、面板收起、`Esc` / 点面板外收起。**格子不加宽、不新增可见性元素** —— 命中区由
`Toolbar::hit` 从序号格子的矩形里折出来（`badge_corner`），不额外塞一条 `hits`，
因为 `hits` 同时驱动绘制与显隐计数。

**放置后改（双击分流）**：

- **符号徽标（✓ / ×）双击 = 直接互相切换**，一次 `Ctrl+Z` 可回退。只有两种值，切换是最省的操作；
  原来的「双击 → 输入框 → 打 `x` → 回车」是四步。想把它改成编号：选中后点格子右下角 ▾ 选「数字」
  （下拉已对选中对象生效）。
- **编号徽标双击 = 进内容编辑**（复用文本输入状态机）：输入框接受**数字**（编号）、
  **`v` / `√` / `✓`**（对勾）、**`x` / `×` / `✕`**（叉号），**不需要输入法**；
  以**最后出现的有效字符为准**（框里已有 `✓` 时直接补一个 `x` 就是叉号，不会被旧内容抢走）。
  也就是说「编号改符号」两条路都通：编辑框打 `x`，或选中后走下拉。

### 5. 形态与选中对象

与颜色 / 线型 / 渐变同一套语义：**有选中徽标时切换形态直接改该对象并进一次撤销**，没选中就只影响下一次绘制
（`objedit::apply_mark_to_selected`）。当前形态跨截图记忆（`config.badge_mark`，`badge_store` / `badge_take`
静态槽，写法同 `line_store`），旧配置缺字段回退自动编号。

## 未采纳方案

- **三个独立工具（序号 / 对勾 / 叉号）**：宽度超限（见决策 1），且绘制、命中、滚轮字号、快捷键、
  可见性开关全部 ×3。
- **图章库**（箭头、星形、表情、问号……）：需求没有上限，与撤销 OCR 的理由同源（ADR 0035）。
  只做语义明确的「对 / 错」两种，其它符号用户可以用文本工具自己打。
- **任意 1~2 字符标签**：技术上不难（`TextEdit` 本来就有完整输入法支持），但会把「序号」这个已经清晰的
  语义糊掉。真有人要，再给 `Badge` 加一个 `Text(String)` 变体就是几十行。
- **双击格子循环切换形态**：零 UI，但只有用过「色块单击用 / 双击换」的人才知道，发现性明显更差。
- **双击统一进输入框编辑**（首版实现）：改一个 ✓ / × 要走「双击 → 输入框 → 打字符 → 回车」四步，
  而实际批注里改符号远比改编号频繁。两者合并会两失（改符号太累、改编号也不快），所以按形态分流。
- **用字符 `✓` / `✕` 直接绘制**：见决策 3。
- **形态有独立快捷键**：序号键已占一个（默认 `7`），再给两种形态各一个键只会让键表更挤，与线型
  「无快捷键」的取舍一致。

## 影响

- 工具栏：**可见性元素数不变（24）**，第一行宽度不变；序号格子里改画当前形态的缩略徽标 + 右下角 ▾
  （`render::badge_preview`，与下拉项、画面上的徽标共用一份绘制）。
- 取消分层回退多一层：取色面板 → 线型下拉 → **徽标形态下拉** → 字体面板 → 文本输入 → 确认 → 退出
  （`annotate::cancel`，有单测守门）。
- 配置新增 `badge_mark`（`num` / `check` / `cross`，缺省 `num`），写回时机同 `line_style`（`WM_OVERLAY_DONE`）。
- `render::mod` 拆出 `render/badge.rs`（徽标绘制 + 半径 + 预览 + 反色），两个文件都回到 300 行内。
- 两处下拉的公共几何抽到 `overlay::toolbar::menu`（行高 / 贴边翻转 / 行命中 / 悬停），
  线型与徽标形态各自只留宽度常量与绘制。**连带的行为变化**：线型下拉的横向定位从
  「左缘对齐格子」改为「对着格子居中」（96px 面板对 52px 格子，左移最多 ~35px），
  纯视觉微调，命中与功能不变——两处共用一份几何就必须统一一种对齐，居中更符合直觉。
- 测试：编号不被符号占用、三路编辑映射（含「后打的字符说了算」）、双击切换只对符号生效、
  `accepts_char` 与 `parse_edit` 的定义互不遗漏、符号绘制有反白笔画且不越出圆、
  符号与一位数字同半径、格子右下角命中下拉而其余仍是工具、下拉行命中与缩放、配置往返。
