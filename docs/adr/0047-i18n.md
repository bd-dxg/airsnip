# 47. 界面国际化一期（I18N）—— 分区域文案键 + 编译期嵌入 + 按量宽自适应布局

- 状态：已采纳（v0.15.0，分批落地；本 ADR 随 B1 批次写）
- 影响范围：新增 `src/i18n/**`、`scripts/check-i18n.ps1`；
  改动 `settings/**`（6 页文案 + `[ui] language` + 工具栏页列数）、`render/text.rs`（界面字体）、
  `output/quick.rs`（变量说明与保存错误）、`update/state.rs`（按钮文案）、`app/mod.rs`（启动解析语言）、
  `diagnose/text.rs`（缩放短标签）
- 相关：issue #151 / ADR 0014（技术标识 ASCII 划分）/ ADR 0016（界面缩放）/ ADR 0033（工具栏显隐键）/
  ADR 0041（设置面板几何与保存页）

## 背景

界面文案全部写死在源码里（`src/` 下约 1486 处含中日文的字符串字面量，其中用户可见约 283 条）。
后果有两层：非中文用户只能看图标猜按钮；同一概念（「荧光笔」「贴图」「保存」）在设置面板、
工具栏提示、托盘菜单各写一遍，措辞漂移没有单一入口。

issue #151 已经定了大方向（编译期嵌入、键名 `区域.对象.项`、不引 ICU、日志与断言不翻译）。
本 ADR 只记录**实现时不得已做出的结构选择**，以及实测数据推翻的假设。

## 决策

### 1. 文案键按区域拆成多个枚举，每门语言每个区域写一个完整 `match`

`Key` 是汇总枚举，`Key::Settings(SettingsKey)` 是第一个区域（B1 批次只迁设置面板）。

```rust
pub enum Key { Settings(SettingsKey) }
keys!(SettingsKey { NavGeneral, NavToolbar, /* …130 条… */ });
```

每门语言对每个区域写一个 **没有 `_ =>` 兜底分支** 的 `match`：

```rust
// src/i18n/en.rs
pub(super) fn settings(k: SettingsKey) -> &'static str {
    use SettingsKey::*;
    match k { NavGeneral => "General", /* … */ }
}
```

**为什么不用一个大枚举 + 一张表**：283 条文案 × 4 门语言 ≈ 1100 行，单文件超 300 行硬上限；
而「漏一条文案」如果只靠运行时兜底，表现是英文界面里突然冒出一句中文 —— 这类漏网是最大的返工来源。
按区域拆之后，**漏项是编译错误**，同时每个文件落在 150 行以内。

**为什么不用 `&[(Key, &str)]` 查表**：静态数组要保证排序/长度一致才能查，错位是静默错误；
`match` 生成跳转表，查表 O(1) 且无分配，与「待机 ≈0 开销、工具栏每帧绘制」的要求一致。

### 2. 语言在全局 `AtomicU8` 里，**改语言立即生效**（不等重启）

issue 原写「进程内不热切换」，指的是不去做外置资源的运行时重载。本实现是纯内存查表：

- 启动时 `app::run` 调一次 `i18n::set_current(cfg.language.resolve())`，早于托盘 / 热键 / 面板；
- 面板里选完语言 → `set_current` → 下一帧 `WM_LBUTTONDOWN` 的 `repaint_full` 就换语言。

代价为零，收益是用户点完立刻看到效果（面板布局每帧重算，不需要重建窗口）。
托盘 tooltip 与已缓存的字符串在下次更新时自然变，不额外通知。

### 3. `Config.language` 走**容错反序列化**，不走 `derive(Deserialize)`

这是本批次唯一的真风险点。`Config` 是 `#[serde(default)]` 结构，但 serde 的 `default`
只在字段**缺失**时生效；字段值不认识时 `toml::from_str` 会失败，而 `Config::load` 的兜底是
`unwrap_or_default()` —— **整份配置连同用户的热键、保存路径、工具栏隐藏项一起被重置**。

旧配置里写的是 `"zh-CN"`（v0.14 及更早），也就是说每个老用户都会踩到。

因此 `LangPref` 手写 `Serialize` / `Deserialize`：

| 输入 | 结果 |
|---|---|
| `auto` | `Auto` |
| `zh-Hans` / `zh-CN` / `zh-SG` / `zh` | `ZhHans` |
| `zh-Hant` / `zh-TW` / `zh-HK` / `zh-MO` | `ZhHant` |
| `en` / `ja` | 对应语言 |
| **任何其它值**（未来新增语言、垃圾值、空串） | `Auto`（跟随系统） |

单测 `toml_deserialize_never_fails_on_language` 与 `unknown_config_values_are_tolerated` 守这条。

### 4. 界面字体按语言取，标注内容字体**不动**

`FontSpec` 拆成两个构造函数：

| 构造函数 | 字体族 | 用在哪 |
|---|---|---|
| `FontSpec::new(size)` | `Lang::ui_family()` | 界面文案：设置面板、工具栏提示、长截图条、Toast、HUD |
| `FontSpec::content(size)` | `editor::DEFAULT_FONT_FAMILY` | 标注内容：徽标数字、序号编辑框 |

字体族映射：简中 `Microsoft YaHei UI`（**与引入 i18n 前完全一致，中文用户零变化**）/
繁中 `Microsoft JhengHei UI` / 英文 `Segoe UI` / 日文 `Yu Gothic UI`。

标注文本对象自带 `font_family` 字段（字体面板可选），本来就与界面字体无关；
顺带把徽标数字与序号编辑框从 `new` 改成 `content`，否则标注导出的字形会随界面语言变 ——
那与「标注不随界面缩放」是同一条原则（界面偏好不改变输出结果）。

字体族缺失时不额外查询 `render::fonts::families()`：DirectWrite 对未知族名会走自己的 fallback 链，
文字不会变成豆腐块，只是字形风格退化成系统默认；为此在每次绘制前枚举几百个字体族不值得。

### 5. 工具栏页列数由**量宽**决定，不写 `if lang`

实测（DirectWrite，16px，`examples` 下的临时探针，用完删除）：

| 位置 | 可用宽 | 中文最长 | 英文最长 | 日文最长 |
|---|---|---|---|---|
| 工具栏格（5 列） | **55px** | 荧光笔 48 | Quick save 75.7 | グラデーション 80.6 |
| 工具栏格（4 列） | 83px | — | Freehand 65.8 | スポットライト 80.8 |

5 列放不下英文与日文，于是列数改成 `toolbar_columns(lang, scale, width)` 计算：
从 5 往下试，取第一个能装下「最长标签 + `CELL_PAD×2` + `TOGGLE_W`」的列数。
中文自动得 5 列（与今天完全一致），英文 / 日文自动得 4 列。

**不写 `if lang`**：issue R2 要求「加第三门语言的成本 = 一个资源文件 + 一条字体映射」。
代价是行数从 7 变 8、内容高超 H 8px，所以 `toolbar_row_h` 按「能装下且给页脚提示留位置」
收缩行高（4 列时 45 → 41）；5 列中文算出来仍是 46，老路径零变化。

`toolbar_columns_follow_label_width` 断言四种语言各自的列数，
`toolbar_cells_fit_label_and_toggle` / `toolbar_page_fits_height_for_every_language` /
`row_labels_do_not_overlap_controls` 按 4 语言 × 4 档缩放守住溢出。

### 6. 文案表里刻意缩短的标签

英文 / 日文为塞进单元格用了短词（这是布局约束，不是文风偏好）：

| 键 | 长写法 | 采用 |
|---|---|---|
| `ToolHighlight` | Highlight (65.4px) | `Marker` / マーカー |
| `ToolLongshot` | Long screenshot | `Long shot` / 縦長撮影 |
| `KeyResetAll` | Reset all settings | `Reset all` / すべて初期化 |
| `GeneralOpenLogFolder` | Long screenshot log (no passwords, safe to delete) | `Long shot log (no passwords)` |

中文侧的 `SlotQuickSave` = 「快存」是 v0.13.0 就有的妥协（`快速保存` 64px 塞不进 5 列格），
不是本批次引入的。

### 7. 校验脚本按批次推进，而不是一次性拦全部

`scripts/check-i18n.ps1` 用两份清单：`$MIGRATED`（命中即失败）与「其它文件」（只统计）。

- `$MIGRATED` 现在 = `src/settings/`、`src/update/state.rs`、`src/output/quick.rs`；
- 其余 245 处属 B2（覆盖层）/ B3（长截图）/ B4（app 系统串），分批迁完后把路径加进 `$MIGRATED`。

规则：只认字符串字面量里的 CJK；跳过 `#[cfg(test)]` + `mod tests` 块、日志 / 断言、
`*_tests.rs` 纯测试文件、`src/i18n/`（语言表本身就是文案）；
行尾 `// i18n:keep` 是有意保留的白名单（当前只有已退役的 `NameStyle::title`）。

脚本用 UTF-8 **带 BOM** 保存：Windows PowerShell 5.1 对无 BOM 的中文脚本会按 ANSI 解码，
注释里的中文会破坏引号配对（本批次踩过一次）。

## 后果

- **中文界面与 v0.14.0 逐字一致**（唯一例外是 `NameStyle::title` 这类已退役死文案仍留中文、不迁移）。
- 非中文系统首次启动即英文界面，不需要先配置。
- 面板尺寸常量（`W=720`、`H=520`、`NAV_W=124`）**不用按语言变**：实测英文最长导航项
  `Appearance` 84.2px < 124，整行标签最长 237px < 288；只有工具栏页需要按量宽降列。
- 新增语言的成本：`src/i18n/xx.rs` 一个文件（4 区域 match）+ `Lang` 一个变体 +
  `ui_family` 一行 + `LangPref` 一个变体，代码里没有语言分支。
- 未做：RTL（自绘像素布局没有 bidi 能力）、README 多语言、`[ocr] language`（OCR 已于 ADR 0035 撤销，
  设置面板里的 `Config.language` 现在就是界面语言，没有第二条识别语言链需要解耦）。
- 已知边界：`scripts/check-i18n.ps1` 按行匹配，跨行字符串 / raw string 会漏检；
  它挡的是「新增硬编码」，不是翻译质量。zh-Hant / ja 译文未经母语者校对。
