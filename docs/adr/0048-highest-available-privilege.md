# 48. 权限按账户能力取最高（highestAvailable）—— 标准用户也能跑

- 状态：已采纳（v0.14.0 之后）
- 影响范围：`app.manifest`（一行权限声明）、`src/app/elevation.rs`（新增）、
  `src/app/tray.rs`（未提权提示）、`src/app/autostart.rs`（`/RL` 跟随权限）、
  `src/app/wndproc.rs`（注释口径）、`src/diagnose/text.rs`（反馈文本首行）
- 相关：issue #198、ADR 0003（被本文修订）

> 编号说明：本决策起草时占用 0047，i18n 一期（ADR 0047）先合并进 `main`，本文因此顺延为 **0048**。
> 分支名 `feat/highest-available-198` 与提交历史里的「ADR 0047」均指本文。

## 背景

issue #198：用户在公司电脑上双击 AirSnip，弹「需要管理员权限」，但**既不能点「是」也不能输密码**——
账户只在 `Remote Desktop Users` 组，机器由 IT 统一管理、组策略限制提权。表现为程序完全跑不起来。

ADR 0003 的语境是「自备机器 + 管理员账户」：`requireAdministrator` 的实际效果是「管理员账户自动提权」，
用户按一次「是」即可。对标准用户，同一条声明的效果却是**根本不能启动**——这是当年决策时没区分的第三种情况。

## 决策

### 1. `requestedExecutionLevel` 从 `requireAdministrator` 改为 `highestAvailable`

| 账户 | 现状（requireAdministrator） | 改后（highestAvailable） |
|---|---|---|
| 管理员 | 自动提权，点一次 UAC | **完全一致** |
| 标准用户（issue #198） | 弹 UAC 且无凭据可用 → 无法运行 | 不提权、不弹框，以普通权限直接启动 |
| 管理员组但 UAC 关闭 | 全权限 | 全权限 |

选 `highestAvailable` 而不是 `asInvoker`：后者会让**占绝大多数的管理员账户**默认不提权，
截管理员窗口前要先手动重开一次，用默认体验倒退换一个 manifest 词就能解决的问题。

### 2. 未提权时启动弹一次托盘气泡

UIPI（ADR 0003）使普通权限进程盖不住、也截不到以管理员身份运行的窗口（画面黑块）。
不说的话，用户会把黑块当成新 bug 再报一次。因此未提权启动弹一次气泡：

- 标题「以普通权限运行」，正文「管理员窗口可能截不到，需要时请以管理员身份重开。」
  （第一版文案 54 字，托盘气泡只显示得下两行就被截断；标题也不再带 `AirSnip`——
  气泡本就挂在 AirSnip 图标上，重复占宽度）；
- **每次运行只一次**（`AtomicBool` 守门），不落配置（不是「首次安装才提示」，而是每次都要知道）；
- 挂在 `App::ensure_tray` 的成功分支——托盘图标没加上，气泡也无处可挂。

### 3. 自启任务的 `/RL` 跟随当前权限

`schtasks /Create /RL HIGHEST` 在普通权限下会被直接拒绝（Access Denied），而任务本身也拿不到更高权限。
故 `/RL` 取 `HIGHEST`（已提权）/ `LIMITED`（未提权）。开机自启的语义不变：以「当前账户的最高可达权限」启动。

### 4. 反馈文本首行加权限状态

「我要反馈」生成的三行文本首行改为 `AirSnip vX · 普通权限/管理员权限 · Windows…`。
权限是排查「截不到 / 盖不住」时的第一个分支，且用户不会主动说明自己是标准用户。
不加进「开关」行——它是运行环境，不是用户可切换的设置。

### 5. 不做的

- **不提供「以管理员身份重启」按钮**：标准用户下提权的唯一出口是 UAC 凭据输入，
  而这正是本 issue 里不存在的东西；管理员账户本来就是自动提权，按钮没有场景。
- **不提供「以管理员方式启动」开关**：对管理员账户是空操作（本来就是自动提权），
  对标准账户是永远无效的废控件（会让人以为开了就能截管理员窗口）。唯一能实现的形态是
  「`runas` 重启并提权」，代价是面板关闭、托盘重建、热键重注册、未保存编辑全丢——
  而它真正有用的场景只有「管理员组但当前未提权」，`highestAvailable` 下只剩
  「先用标准账户开过自启（`/RL LIMITED`）、后被提成管理员」这一条极窄路径。
  若日后真出现第二个用户报同场景，正确形态是「关于」页的**条件按钮**
  （仅当 `IsUserAnAdmin()` 且未提权时显示），而不是开关。
- **不做降权 / 双 exe 分发**：`highestAvailable` 已经覆盖两种账户，多一个包只会增加分发与文档成本。
- **不在设置面板常驻显示权限**：气泡已经提示过，面板不为此加一行。

## 影响

- 更容易：标准用户（公司 / 学校 / 精简系统）能正常安装运行；dev 构建（`asInvoker`）与发布构建的
  权限语义从此只差「最高可达」，而不是「能跑 / 不能跑」。
- 更难的取舍：标准用户下截不到以管理员身份运行的程序窗口（覆盖层可能被压下去、`BitBlt` 得到黑块），
  这是拿能力换「能运行」，已在气泡里说明。
- 已知边界：
  - `TokenElevation` 查询失败按**未提权**处理——最坏结果是多弹一次提示、自启降一级，都不影响运行；
  - 自动更新替换 exe 需要目标目录写权限：标准用户装在 `Program Files` 下时仍会失败，
    与本次改动无关（此前这类用户根本装不上）。
