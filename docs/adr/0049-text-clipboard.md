# 49. 文本标注与系统剪贴板互通（粘贴 / 复制 / 全选），但**不做任意区间选区**

- 状态：已采纳（v1.0.0 之后）
- 影响范围：`src/overlay/textinput.rs`（按键分发）、`src/overlay/textinput/clip.rs`（新增）、
  `src/overlay/textinput/draw.rs`（全选高亮 + 提示绘制）、`src/overlay/text_edit_state.rs`（全选 / 粘贴状态）、
  `src/overlay/wndproc/keydown.rs`（编辑态的 `VK_PROCESSKEY` 翻译）、
  `src/overlay/selection/mod.rs`（输入框脏区）、`src/i18n/**`（4 条新文案）
- 相关：issue #220、ADR 0004（自绘文本、不用系统 `EDIT` 控件）、ADR 0034（IME 候选框跟随光标）、
  issue #221（文字超出选区自动换行，本文不涉及）

## 背景

issue #220：截图里用文本工具写的字，与系统剪贴板**两个方向都不通** —— 别处复制的文字贴不进标注，
标注里写好的文字也拿不出来，只能重新手打。

底层能力其实早就在（ADR 0041 的「保存路径模板」框已经能 `Ctrl+V`，SYS-8 的「我要反馈」已经在写
`CF_UNICODETEXT`），缺的是**把它接到文本输入态上**。真正需要决策的是第二半：issue 期望的是
「选中文字后 `Ctrl+C`」，而自绘文本输入（ADR 0004）**只有光标，没有「选中」这个概念** ——
没有选区字段、没有拖选、没有 `Shift` 扩选、没有选中高亮。

## 决策

### 1. 粘贴：`Ctrl+V` 把剪贴板文字插到光标处

- 归一化：`\r\n` 与 `\r` 统一成 `\n`（Windows 剪贴板里全是 `\r\n`，不归一每行之间会多一个空行），
  其它控制字符丢弃（含制表符 —— 自绘排版按字符量宽，制表位无处锚定）。
- **上限 4096 字符**，超出截断并明确提示「已粘贴（截断至 N 字）」。不设限的话，粘一整篇文档进标注
  会让 `caret_x` / `region` 每帧 DirectWrite 量宽，按键与重绘肉眼可见地卡；静默截断比上限本身更糟，
  所以截断必须说出来。
- 剪贴板里没有文字（只有图片 / 空白 / 全是控制字符）时提示「剪贴板里没有文字」，不静默无反应。

### 2. 复制：`Ctrl+C` 复制**全部**已编辑文字，不引入任意区间选区

本批只做「全选 / 无」两态：

| 操作 | 行为 |
|---|---|
| `Ctrl+A` | 全选：整块文字盖一层半透明蓝底（可见确认，否则按下去屏幕上什么也不变，用户以为键坏了） |
| `Ctrl+C` | 复制全部已确认文字（不含 IME 组合串 —— 还没落定的东西不该被复制），提示「已复制 N 字」 |
| `Ctrl+V` / 直接打字 | 有全选时**替换全部**（标准编辑器的选区语义） |
| 方向键 / `Home` / `End` | 只收掉全选，不删字、不扩选 |

选它而不是完整选区模型的理由：

1. issue 的实际诉求是「把写好的那段文字拿出去」，全选 + 复制已经覆盖；「只复制其中一句」的频次远低于前者。
2. 任意选区要连带一整套：选区字段与锚点、`Shift` 扩展、鼠标拖选、**按行拆条的选中高亮**
   （多行文本的高亮不是一块矩形）、删除 / 替换 / 剪切的边界处理。这套东西和 issue #221
   （自动换行）改的是同一段排版代码，先做一份小的、等 #221 落地时一起重做，比现在写两遍划算。
3. 全选高亮可以是**一块矩形**，20 行代码；按行拆的选区高亮不是。

`Ctrl+C` 的既有语义（复制截图并退出）保持不变：**只有在文本编辑态才抢**。这一点天然成立 ——
编辑态按键在 `wndproc::keydown::on_keydown` 开头就整体转给 `on_text_key` 并 `return`，
全局 `Ctrl+C` 根本进不来，不需要动优先级判定。

### 3. 提示是「输入期的一次性反馈」，不新增定时器

「已复制 N 字」画在输入框下方（下方塞不下翻上方、钳回屏幕内），**活到下一次按键**就被清掉。
不用 `toast` / `cancel_hint` 那套定时器，因为：文本编辑本来就是按键驱动的，下一次按键必然到来；
而新增一个 `WM_TIMER` ID 就得再守一次「ID 不与其它用途撞车」（ADR 0041 踩过：吸附动画的定时器
把覆盖层当成「提示到点」关掉）。

提示画在输入框**之外**，所以清掉时 `region()` 就不再包含它 —— 必须把它原来的矩形单独重绘一次，
否则「已复制」会永远留在屏幕上。这条约束写进了 `Overlay::drop_text_hint` 的注释里。

### 4. 脏区取「选区 ∪ 输入框」

原先输入态重绘只重绘选区，但输入框可能超出选区（#221 尚未做换行），框外那部分文字与提示本来就会留残影。
改成 `union_rect(选区, 输入框 region)` 顺带把这块补上，成本是每次按键多算两个矩形。

### 5. 编辑态只在带 `Ctrl` 的组合键上翻译 `VK_PROCESSKEY`

中文输入法待输入时，`WM_KEYDOWN` 的 `wparam` 会被改写成 `VK_PROCESSKEY(0xE5)`、真实键另存
（按键分发里非编辑态早就在用 `ImmGetVirtualKey` 取回，M4 老问题）。编辑态此前不做这个翻译，
于是**输入法开着时 `Ctrl+V` 会拿到 0xE5、粘贴失效**。

只在 `ctrl_down()` 时取真实键，而不是无条件翻译：打拼音时的退格必须留给输入法删组合串，
无条件翻译会变成「删我们自己缓冲的字符」，那是另一个 bug。

## 不做

- **任意区间选区**（拖选 / `Shift` 扩选 / 只复制其中一句）：理由见决策 2，等 #221 一起做。
- **`Ctrl+X` 剪切**：没有区间选区时它就是「清空全部」，收益为零、误触代价大。
- **`Win+V` 系统剪贴板历史**：最初列为「待实测」（它是系统热键、面板由 explorer 弹出，选中条目后能否送进
  我们的自绘光标取决于系统给前台窗口发什么）。**实测（Windows 11）可用**：选条目后等于往剪贴板写回并
  向前台窗口发一次 `Ctrl+V`，因此 `Ctrl+V` 一通它就跟着通，**没有专门适配、也不需要**。
- **富文本 / 保留原格式**：`CF_UNICODETEXT` 只给纯文本，标注也只存纯文本。

## 边界

- 贴图标注编辑（ADR 0028）走同一套输入态，因此同样支持；徽标内容编辑（EDT-12 / EDT-20）**不支持** ——
  那里只收单个数字或 ✓ / ✕，粘贴与全选在 `handle_clip_key` 开头就早退。
- 复制失败（剪贴板被别的程序占着，`OpenClipboard` 会失败）不弹框，只给「复制失败，请重试」。
- 粘贴不触发撤销栈：整个输入态在提交时才入一次撤销（既有语义，未改）。
